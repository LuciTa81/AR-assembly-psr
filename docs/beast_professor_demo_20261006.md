양안 SBS 표시와 눈별 보정 후보를 구현하여 나사 A 참조 원과 단계 문구를 연속 표시하도록 연결했습니다.

## 19:10 연속 SBS 연결

- 단일 카메라 서버에서 상태 추론과 위치 관측을 함께 생성합니다. 카메라를 여는 별도 시험 서버는 실행하지 않습니다.
- Unity의 새 `-CandidatePresentation` 모드는 현재 단계/작업/보류 문구와 A 고정 참조 원을 함께 표시합니다.
- 크롬은 같은 서버의 카메라 투영 영상과 현재 상태를 표시합니다. 안경 속 광학 합성 화면의 녹화는 아닙니다.
- 자동 종료 제한은 없습니다. 추적 유실/오래된 관측/세션 불일치에서는 원을 숨기고 안내 문구를 남깁니다.
- Full SBS 3840x1080 + 0DoF + 확장 모드를 유지합니다. 출력 모드 변경 시 다시 실행해야 합니다.
- A 원은 미검증 후보이며 B/C/D로 자동 전환하지 않습니다. 깜빡임과 정합 정확도가 해결됐다는 뜻은 아닙니다.
- 기존 `-StereoAlignmentProbe` 및 다운로드 폴더의 `Start-SBS.cmd`는 여전히 30초 시험입니다.

위치 관측이 포함된 서버를 `--presentation-config <camera/workspace JSON>`으로 실행한 뒤,
서버가 출력하는 **현재 세션**의 `Presentation client config` 경로를 사용합니다.

```powershell
.\scripts\run_beast_unity.ps1 -Beast -CandidatePresentation -CandidateProjection <candidate-probe.json> -DisplayObservationConfig <current-client-config.json>
```

Unity 종료는 Q 또는 Esc입니다. 서버와 크롬은 별도로 유지됩니다. 아래의 분리 모드 설명은 기존 시험 경로입니다.

## 현재 구현 수준

| 부분 | 구현 및 확인 범위 | 남은 한계 |
| --- | --- | --- |
| 입력 | Beast 카메라를 노트북에서 수신 | 재연결 시 카메라 번호 확인 필요 |
| 인식 | ArUco 정렬, ROI 점수, YOLO 도구 관측 | 가림과 자세 변화, 나사 접근/이탈 판정 안정화 필요 |
| 실시간 상태 | 시간 기반 관측 유지, 접근/이탈, 유실 시 보류 | 전 구간 반복 성공률은 아직 측정 전 |
| Unity | Windows 실행 파일, Beast 확장 화면, 상태/다음 작업/보류 문구 | 실제 나사 위치에 고정된 안내와는 구분 |
| 관제 웹 | 선택적 원본 카메라 영상, 단계, 안내, 보류 이유, 추적/FPS | 눈으로 보는 광학 합성 화면의 녹화가 아님 |
| 공간 좌표 | 카메라 보정, 실측 마커 배치, A-D 좌표, 카메라 투영 | 안경 재착용/설정 변경 시 눈별 정합 재확인 필요 |
| SBS | 3840x1080을 좌우 눈별 1920x1080으로 분리, 눈별 대응점 수집/투영 | 사용자별 보정 필요 |
| 자동 공간 표시 | 나사 A의 후보 원이 관측에 따라 갱신되는 시험 | 사용자 피드백: 대략 A 근처이나 깜빡임 심함. 정밀 정합 통과 아님 |

Unity는 VITURE XR SDK나 Neckband 앱이 아니라, 노트북에서 실행되는 C# 클라이언트입니다.
현재 서버 연동은 로컬 HTTP JSON 조회입니다. AWS, KVS, IVS, SafeOps 클라우드는 아직 붙이지 않았습니다.
실시간 경로는 `timed_v1` 상태 필터이며, 전체 시퀀스를 보는 오프라인 Viterbi와 구분합니다.

## 시연 순서 (3~5분)

1. 대시보드에서 `영상 표시`를 켜고 안경 움직임을 따라 영상이 움직이는지 확인합니다.
2. 작업자가 Beast의 단계/다음 작업 문구를 보고, 교수님은 노트북에서 같은 상태와 근거를 봅니다.
3. 추적이 끊길 때 임의로 다음 단계를 확정하지 않고 보류하는 동작을 보여줍니다.
4. 연속 SBS 모드에서는 같은 입력으로 단계 안내와 A 참조 원을 함께 보여줍니다.
5. SBS는 공간 정합 후보 시험이고 깜빡임이 개선 과제임을 설명합니다. 불편하면 즉시 Q로 종료합니다.

기존 30초 시험에서는 단계 안내와 A 원 후보 추적이 별도 실행 모드입니다.
두 Python 프로세스가 같은 카메라를 동시에 열면 안 됩니다.
SBS 시험 중 관제 웹의 기존 상태가 끊기는 것은 모드 전환 때문이며, 그 상태를 실시간 결과로 설명하지 않습니다.

## 현장 운영

- 가장 안정적인 시연은 현재 작업대에 교수님을 모시는 것입니다.
- 이동해야 하면 실행을 종료하고, 노트북을 잠자기 상태로 만들지 않도록 하며 현장에서 다시 실행합니다.
- 상자와 마커를 개별로 옮기면 기존 등록 위치가 달라집니다. 매트 위 상대 위치를 보존해야 합니다.
- 안경을 교수님께 넘겨 착용하게 할 경우 본인용 눈별 보정의 정합을 보장할 수 없습니다.
- 단계 안내는 일반 2D + 0DoF, A 원 시험은 Full SBS + 0DoF를 사용합니다.
  Windows 확장을 유지하고 화면 크기/거리 설정은 바꾸지 않습니다.
- 영상은 로컬 화면에만 표시하며 사진/영상 저장과 외부 전송은 하지 않습니다. 상태 메타데이터 로그는 남습니다.
- 시연을 위해 임계값을 낮추거나 상태를 완료로 강제하지 않습니다.

## 질문별 답변

### Unity에서 직접 한 일은 무엇인가?

Python 서버와 화면 표시를 분리하고, C#에서 상태 JSON을 받아 상태별 안내 문구와 유실/지연 상태를 표시했습니다.
Beast 확장 디스플레이 선택과 전체 화면 출력을 구현했고, Full SBS에서는 눈별 화면을 분리합니다.
수동 눈별 정합과 좌표 수집 도구를 만든 뒤, 카메라 좌표를 각 눈의 픽셀로 투영하는 후보 모드를 추가했습니다.

### 인식 정확도는 얼마인가?

1학기 session17의 오프라인 HMM 결과는 accuracy 94.12%, macro-F1 94.85%였습니다.
이 값은 현재 실시간 시스템의 정확도가 아닙니다. 실시간 상태 전이 정확도, 지연, 오전이율은 별도 반복 평가할 계획입니다.

### 나사를 실제로 조였다는 것도 확인하는가?

현재는 시각적 도구 접근/이탈과 상태 증거를 관측합니다. 실제 체결 토크나 완전 체결을 보증하지 않으며,
완료 단계에서도 사용자의 최종 확인이 필요합니다.

### 다음 개발 순서는?

발표 이후 착용 진단에서 위치 데이터 만료가 주된 원 숨김 원인으로 확인됐습니다.
수치와 다음 변경 범위는 `beast_tracking_diagnosis_20261006.md`에 기록했습니다.

1. 카메라 재연결 후 장치 선택과 마커/pose 유실, 데이터 만료 원인을 분리하여 A 원 깜빡임을 줄입니다.
2. 보정에 쓰지 않은 자세에서 눈별 오차, 깊이감, 재착용 영향을 확인합니다.
3. A 원이 안정된 뒤 안경의 A-D 연결선과 단계별 목표 화살표를 추가합니다. 상태 안내와 A 참조 원은 한 입력 경로로 연결됐습니다.
4. 여러 세션에서 상태 전이, 표시 지연, 정합 오차, 추적 손실/회복을 평가합니다.
5. 원격 관제와 서버 분리는 이 로컬 흐름을 안정화한 뒤 필요 범위에 한해 적용합니다.
