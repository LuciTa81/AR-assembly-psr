# C/D 거리 보정과 202mm 후보: 오프라인 검토

## 결론

기존 C/D 보정 함수를 재사용할 수 있다는 수치 근거는 있다. 그러나 원본 파일을 새 후보에 그대로 연결하는 것은 현재의 해시 검사에서 거절되며, 이를 우회하거나 원본 관측을 수정하지 않았다. 실시간 적용과 실물 양안 검증은 아직 하지 않았다.

이번 변경은 오프라인 C# 테스트 한 개와 테스트 프로젝트 등록, 숫자 보고서뿐이다. 기존 성공본, A-D 목표 좌표, 눈 투영 행렬, C/D 보정 6개, 거리 제한, 실행 코드와 Unity 실행 파일은 유지했다. 카메라와 Unity 앱은 실행하지 않았다.

## 검증 방식

1. C/D 각각 가까운·중간·먼 거리의 저장 관측과 같은 프레임의 마커 모서리를 연결했다. 기존 작업대 설정으로 다시 계산한 카메라 좌표는 원본 6개와 모두 일치했다(검사 허용차 1e-6mm).
2. 카메라와 목표 좌표는 유지하고, 1번 마커 X만 205mm에서 실측 202mm로 바꿔 같은 마커 관측을 재계산했다.
3. 실제 Unity 소스의 `TargetDepthTrial`을 순수 C# 테스트에서 호출했다. Python으로 거리 보정 공식을 따로 흉내 내지 않았다.
4. 원래 프로필에 연결된 보정 함수에 기존/새 카메라 좌표를 각각 넣어 표시 가능 여부, 눈별 위치 변화, 양안 시차 변화를 비교했다. 이는 새 프로필에 실제로 연결한 런타임 시험이 아니다.
5. 새 후보에 원본 C/D 기록을 직접 넣으면 거절되는지, 잘못된 대상/후보 연결과 거리 범위 밖 입력도 거절되는지 확인했다.

총 3,035개 **대상별 비교 사례**를 검사했다. 같은 카메라 프레임을 C와 D에 각각 평가한 사례도 있으므로 독립 프레임 3,035개나 사용자 실험 3,035회가 아니다. 원본 보정점 6개, 이전 실제 C/D 작업 1,759프레임, 나머지 카메라/A 시야 자료는 구분해서 집계했다.

## 이전 실제 작업 로그 3개

| 대상 | 비교 프레임 | 기존 표시 계산 가능 | 202mm 계산 가능 | 추가 | 기존 가능 사례 상실 | 눈별 위치 변화 최대 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| C | 888 | 777 | 781 | 4 | 0 | 8.20px |
| D | 871 | 685 | 756 | 71 | 0 | 6.46px |

위치 변화는 양쪽 설정 모두 표시 계산이 가능했던 사례에서 두 눈 중 큰 변화량이다. 실제 나사 대비 오차가 아니다. 세 작업 로그에서 세로 양안 시차 변화의 최대값은 C 0.681px, D 0.224px였다. 편안함이나 깊이 정확도를 증명하는 수치는 아니다.

원래 표시 계산이 가능했던 1,462건은 모두 유지됐고, 75건이 추가됐다. 추가 사례에는 기존 통과 좌표나 실물 정답이 없으므로 위치 정확도 개선으로 해석하지 않는다. 이 재현은 입력 만료, 네트워크, Unity 상태 채널 등 시간 조건을 포함한 실제 표시율 측정이 아니다. C의 긴 마커 소실도 해결하지 않는다.

## 거리 끝점에서 발견한 제한

원본 보정 함수는 저장한 가장 가까운/먼 카메라 Z 범위 밖을 표시하지 않는다.

| 대상 | 기존 Z 범위(mm) | 가까운 점을 202mm로 재계산한 Z | 기존 최솟값보다 작은 양 |
| --- | --- | ---: | ---: |
| C | 305.965364 ~ 531.041828 | 305.952752 | 0.012612mm |
| D | 330.240291 ~ 500.501276 | 330.208211 | 0.032079mm |

따라서 보정점 6개 중 가까운 두 점은 새 계산에서 범위를 벗어나 숨겨진다. 이전 실제 작업 1,759프레임에서는 같은 상실이 없었지만, 모든 거리에서 동일하다고 말할 수 없다. 이 값은 카메라 좌표의 Z이며 사용자가 자로 잰 눈-나사 거리와 같다고 가정하지 않는다.

작업대 변경에 따른 보정점 좌표 변화는 모두 0.683mm 미만이었다. 이는 두 계산의 차이이며 독립 실측 오차가 아니다. 이번에는 거리 제한을 늘리거나, 범위를 벗어난 값을 끝점으로 고정하거나, 보정점을 다시 맞추지 않았다.

## 다음 최소 단계

- 원본 후보/기록과 새 작업대의 역할을 분리한 명시적 시험 연결을 마련한다. 카메라·눈 행렬·대상 좌표가 같다는 검사와 원본 해시 검사는 유지한다.
- 첫 C/D 실기는 기존 거리 범위의 내부에서만 비교하고 원본 보정 수치는 유지한다. 자동 단계 진행이나 가림 개선과 동시에 시험하지 않는다.
- 거리 끝점까지 필요하면, 원본을 보존한 별도 경계 처리 후보를 검토한다. 이번 결과만으로 제한을 완화하거나 자동 적용하지 않는다.
- C/D 실물 겹침·깜빡임 확인 후에 전체 A-D 흐름 적용 여부를 결정한다. 현재 자료만으로 C/D 보정을 다시 수집해야 한다고 결론 내릴 근거는 없다.

## 기록과 재현

- 결과 폴더: `outputs/marker1_measured_20261108/cd-offline-20261108T014901Z-ed9aa249`.
- `input.json`: 원본 후보/보정 사본, 같은 입력에서 계산한 좌표, 출처 파일 25개의 SHA256.
- `input.replay.json`: 원래 C# 보정 함수를 사용한 첫 재현 결과.
- `summary.json`: 실제 C/D 작업, 카메라 시야, A 전용 시야, 원본 보정점의 분리 집계.
- `tests/unity/DepthTransferOfflineTests.cs`: 명시적으로 선택할 때만 실행되는 오프라인 테스트. 재실행은 고유 이름의 보고서를 추가하며 이전 결과를 덮어쓰지 않는다.

PowerShell에서 `BEAST_DEPTH_TRANSFER_INPUT`을 위 `input.json`의 절대 경로로 지정하고 다음을 실행한다.

```powershell
dotnet run --project tests/unity/GuidanceTests.csproj --no-restore -- --test=DepthTransferOfflineTests.ReplayImmutableDepthRecordsWithBothWorkspacePoses --noresult
```

신규 오프라인 재현 테스트 1개 통과. C# 전체 회귀 테스트는 338개 통과, 실패 0개, 선택형 로컬 자료 테스트 2개 제외였다(그중 신규 테스트는 위에서 별도 실행). 재실행 결과의 동일성과 출처 파일 25개의 해시 불변도 확인했다. 실기·Unity 빌드·자동 활성화는 수행하지 않았다.

## 후속: 선택적 시험 연결 준비

사용자의 다음 진행 요청에 따라 202mm 전용 연결을 구현했다. 원본 C/D 기록을 수정하지 않고 명시적인 v2 시험 설정에서만 원본 보정 함수를 참조한다. 기존 직접 연결의 해시 검사는 그대로이며, 카메라·눈 행렬·작업대 좌표계·A-D 목표 좌표·기록 파일 해시를 검사한다. 거리 범위는 넓히지 않았다.

- 시험 파일: outputs/marker1_measured_20261108/cd-bridge-20261108T020303Z-0ae26668.
- 별도 실행 파일: outputs/unity_cd202_trial/BeastAssemblyGuide.exe. 기존 성공본 outputs/unity_p1과 기본 설정은 그대로다.
- 신규 연결 코드로 3035개 대상 사례를 재현해 이전 계산과 일치했다. 합성 최신 상태/시계를 사용했으므로 실제 표시율 검증은 아니다.
- 최종 C# 회귀 358개 통과, 실패 0개, 선택형 3개 제외. 실제 자료 연결 재현 1개는 별도로 통과했다.
- Unity의 누락 객체 처리 차이로 기존 설정을 잘못 분류하는 문제를 독립 검토에서 발견하고 실제로 재현했다. 명시적인 버전 분기로 수정했으며 기존/새 설정 모두 실제 Unity JSON 로딩 검사와 별도 빌드를 통과했다.
- 카메라·실기 앱·서버는 실행하지 않았고, 실물 C/D 겹침은 아직 확인하지 않았다. 다음은 사용자 준비 확인 후 기존 거리 범위 내부에서 C/D만 비교하는 시험이다.
