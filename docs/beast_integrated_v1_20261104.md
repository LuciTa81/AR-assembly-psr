## 연결 구조

단일 Python 카메라 입력 → 등록된 작업대의 metric 마커 추적 →
서버가 소유하는 작업 단계 → Chrome 관제 + Unity Windows SBS 문구.

- Chrome: 선택적 영상, A-D 카메라 투영, 상단 나사 연결선, 현재 목표 화살표,
  현재 단계, 추적 상태, 사용자 확인 버튼.
- Unity: 같은 상태 채널의 단계·작업 문구를 양쪽 눈에 표시한다.
  눈 보정이 없어도 문구는 보이지만, 실물 위치 원을 임의로 켜지 않는다.
- 단계는 서버 한곳에서 관리한다. Unity는 카메라나 인식 모델을 실행하지 않는다.
- 사용자 확인은 다음 새 입력에 반영한다. 세션·revision 불일치, 중복 요청,
  오래된 입력, 마커 유실에서는 전진시키지 않는다.
- 서버와 관제는 loopback 전용이다. 사진·영상은 저장하지 않고 숫자 로그만 남긴다.

이번 범위에 없고, 새 작업은 서버를 재시작해 새 세션으로 시작한다.

추적 유실·위치 만료 시 화살표와 연결선을 숨긴다. 기존 150ms 위치 예산과
500ms 상태 예산을 완화하지 않았다. 연결선은 상단 나사 사이의 선이지 전체
상자 3D 모델이 아니다.

## 인식과 정합의 경계

- --guidance-mode operator: 기존 warp/ROI/YOLO 자동 인식을 실행하지 않는다.
  현재 metric 작업대 프로필로 추적하고, 진행은 사용자 확인으로만 처리한다.
- 기존 --guidance-mode auto 경로와 설정은 유지했다. 재사용하려면 현재 작업대
  ROI와 도구 증거의 정확성을 따로 확인해야 한다.
- 기존 후보 A REF 실험은 별도로 유지했다. 통합 실행기는 검증되지 않은
  후보 투영을 자동으로 켜거나 B-D에 재사용하지 않는다.
- 이번 작업은 카메라 프로필·마커 치수·나사 높이·보정 모델을 수정하지 않았다.
  A의 카메라 투영은 제한적으로 확인된 후보이고, B-D와 양안 정합은 미검증이다.
- 뚜껑은 닫기 지시와 사용자 확인만 연결했다. 열림/닫힘 자동 판정과 뚜껑의
  3D 위치 추적은 이 시연 모드에 포함하지 않는다.
