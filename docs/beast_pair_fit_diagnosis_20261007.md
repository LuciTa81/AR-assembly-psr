# Beast 양안 보정 후보 원인 검토 (2026-10-07)

## 결론

사용자가 PAIR SAVED를 확인한 뒤 고개를 움직인 것이 기존 파일을 변경하는 경로는
발견하지 못했다. 선택한 여섯 파일은 원래 분석 보고서에 기록된 SHA-256과 모두
동일하고, 같은 파일로 투영행렬과 양안 기하 경고가 정확히 재현됐다.

확인된 문제는 **현재 여섯 점에 대한 독립 DLT 추정의 높은 민감도**다.
수집점에서 편안하게 겹쳤다는 사용자 확인과 모순되지 않는다. 경고는 사용자의
편안함이나 실제 IPD를 측정한 것이 아니라, 계산된 두 가상 카메라 중심을 검사한다.
원자료에 포함된 작은 오차의 물리적 원인은 아직 완전히 구분하지 못했다.

운영 코드, 원본 보정점, 활성 프로필, 저장/추적 임계값은 변경하지 않았다.
카메라를 켜거나 사진/영상을 저장하지 않았다.

## 1. 저장 후 움직임 가설

코드 경로:

- StereoAlignmentState.PreviewMark는 Enter 시점의 화면 좌표를 별도 객체로 만든다.
- DisplayObservationRecorder.CollectRoutine는 이전 조회가 끝나기를 기다리고
  새 HTTP 조회를 수행한다. 이전 단안 저장 시각을 양안 계산에 재사용하지 않는다.
- Both 저장은 왼눈과 오른눈 화면 좌표를 하나의 공통 카메라 관측과 묶는다.
- 수집 요청 중에는 StereoAlignmentProbe.HandleKey가 위치 변경 입력을 막는다.
- JSON을 임시 파일에 완전히 쓰고 새 point-NNN.json으로 이동한 다음 CommitMark를
  호출한다. 성공 표시 PAIR SAVED는 그 이후에 나온다.
- 다음 Enter는 새 파일을 만든다. 이미 존재하는 파일을 덮어쓰지 않는다.

따라서 PAIR SAVED 뒤 이동은 그 파일을 소급 변경하지 않는다. 단, Enter 직후 아직
CAPTURING인 동안의 움직임 또는 움직인 뒤 다시 Enter를 누르는 것은 구분해야 한다.
후자는 새 관측을 추가한다. 이번 분석은 자동 glob 최신값이 아니라 명시적으로
선택한 여섯 파일만 사용했으며 선택 파일과 해당 Unity 저장 로그도 일치한다.

저장 관측의 age는 약 80.6~111.9ms, 단기 안정성 구간은 약 197.8~516.7ms였다.
이는 현재 수집 계약 통과를 뜻한다. cap.read() 직후 수신 시각을 사용하므로 실제
센서 노출부터의 전체 지연까지 측정한 것은 아니다. 파일과 코드만으로 저장 순간의
사용자 미세 움직임을 완전히 배제할 수는 없다.

## 2. 낮은 fit 오차와 기하 경고가 공존하는 이유

현재 함수 server/realtime/display_fit.py의 fit_projection은 눈마다 3x4 행렬을
독립적으로 추정한다. 공통 배율을 제외하면 눈마다 자유도 11개이며, 여섯 점은
x/y 관측 12개다. 계산 가능한 최소 개수이지 잡음에 강한 보정이 보장되는 개수가 아니다.

- 각 눈 fit 6, check 0. 독립 광학 검증 없음.
- fit RMS: 왼눈 1.475px, 오른눈 2.201px.
- 2번과 3번 자세의 카메라 좌표 간 거리는 약 21.7mm로 비교적 가깝다.
- 전체 XYZ 특이값은 약 148.5/112.8/68.7이다. 공면 퇴화로 단정할 자료는 아니다.
- 정규화 DLT 제약 행렬의 s0/s10은 왼눈 68.9, 오른눈 102.2.
  s10/s11은 각각 6.83, 3.04. 이는 진단 수치이며 새 합격 임계값으로 사용하지 않았다.
- 추정 중심 차이는 (37.1,26.4,86.1)mm, 중심 간 거리는 97.4mm다.
  코드의 양안 기하 휴리스틱이 이 수치에 경고를 냈다.
- 직접 계산 -M^-1 p4와 OpenCV decomposeProjectionMatrix의 동차 중심 좌표가 일치했다.
  눈 중심 분해 계산의 부호/동차 좌표 오류를 이번 경고의 원인으로 보지 않는다.

투영행렬을 내부 파라미터, 회전, 카메라 위치로 분해하는 함수 정의는
[OpenCV 공식 문서](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)를 참고했다.
분해된 위치는 모델 추정치이며 이 안경 사용자의 실측 눈 위치가 아니다.

## 3. 민감도 재현

원본은 수정하지 않고 배열 복사본에서만 실험했다. 아래 수치는 실제 광학 오차나
측정 잡음 분포, 신뢰구간이 아니라 가정한 작은 변화에 대한 계산 반응이다.

### 실제 저장 관측 교체

같은 세션에서 화면 좌표 네 값이 완전히 같은 다른 양안 저장 파일로 한 점만
교체해 재계산했다. 선택 목록은 변경하지 않았다.

| 교체한 자세 | 카메라 좌표 차이 | 추정 중심 간 거리 |
| --- | ---: | ---: |
| 기준 선택 여섯 점 | 0 | 97.4mm |
| 2번을 같은 화면 좌표의 point-004로 교체 | 1.52mm | 174.3mm |
| 3번을 같은 화면 좌표의 point-008로 교체 | 2.81mm | 658.8mm |
| 5번을 같은 화면 좌표의 point-007로 교체 | 1.22mm | 91.4mm |

좋게 나온 조합만 채택하지 않는다. 반복 저장 사이의 차이는 실제 미세 움직임과
마커/카메라 추정 차이가 섞였을 수 있다. 해당 반복을 독립 자세로 추가하지도 않는다.

### 가상 오차 대조

난수 시드 20261007, 조건마다 500회. 화면 각 축에 독립 정규분포 잡음을 추가했다.

| 자료/조건 | 관측 범위 안 가상 점 (0,60,550)mm의 예측 변화 중앙값 |
| --- | ---: |
| 실제 여섯 점, 화면 잡음 표준편차 1px | 13.94px |
| 이상적인 60mm 양안 모델, 현재와 같은 여섯 XYZ, 화면 잡음 1px | 9.60px |
| 같은 XYZ 범위에 고르게 배치한 12점, 이상적인 60mm 모델, 화면 잡음 1px | 0.69px |

예측 변화는 두 눈 중 큰 변화량을 기준으로 한다. 비교용 가상 점은 실제로
정합 여부를 확인한 점이 아니다. 합성 모델의 60mm는 사용자 IPD 가정이 아니며,
활성 보정값으로 사용하지 않는다. 12점 대조는 개수와 배치를 함께 바꾼 비교다.
실제 안경에서 12점이면 반드시 해결된다는 보장이 아니다.

잡음 0인 별도 10회 대조에서는 60mm 중심 간 거리와 예측값이 수치 정밀도 내에서
그대로 복원됐다. 이 실험들은 사용자 정렬 실패가 없어도 현재 수집 분포와 최소
DLT 추정에서 경고/예측 불안정이 발생할 수 있음을 보여준다.

## 4. 아직 구분하지 못한 원인

- 같은 화면 좌표의 반복 저장 사이 카메라 좌표는 최대 약 6.87mm 달랐다.
  정지 고정 장치나 독립 기준이 없으므로 몸 움직임과 pose 흔들림을 분리할 수 없다.
- 짧은 구간 2mm 안정성 통과는 절대 2mm 위치 정확도 보증이 아니다.
- pair 파일에는 마커 코너 원자료와 센서 노출 시각이 없다. 이 자료만으로
  카메라 왜곡, 작업대 치수, 마커별 편향을 다시 풀거나 지연 오차를 검증할 수 없다.
- 단순 핀홀 모델과 실제 안경 광학의 차이, 재착용 없이도 가능한 미세 미끄러짐 등은
  가능한 잔여 요인이다. 현재 자료로 주원인이라고 단정하지 않는다.
- 경고 기준 자체도 광학 실측 기반 합격 기준이 아니라 휴리스틱이다.
  단순히 경고를 없애거나 97mm를 실제 사용자 눈 사이 거리로 해석하지 않는다.

## 5. 다음 최소 범위

1. 여섯 점과 사용자 편안함 확인을 보존한다. 재수집 또는 자동 활성화하지 않는다.
2. 기존 자료로 독립 DLT와 자유도를 줄인 양안 보정 후보를 비교한다.
   실제로 모르는 IPD/광학 파라미터를 임의의 정답으로 고정하지 않는다.
3. 수집 개수만 세지 말고 좌우/상하/거리 배치와 수치 민감도로 보강 위치를 정한다.
   2번/3번처럼 가까운 점을 반복하는 것보다 빠진 공간을 보강한다.
4. 다음 수집 때는 한 자세에서 최종 PAIR SAVED가 확인되면 그 점을 확정하고
   반복 Enter를 멈춘다. 새로 조절할 때에만 새 관측을 명시적으로 선택한다.
5. 새 후보는 계산에 사용하지 않은 자세에서 별도 검증한 후 자동 추적을 시험한다.
   fit 오차 또는 기하 휴리스틱만으로 광학 정합을 통과시키지 않는다.

위 항목은 후속 작업 범위이며 이번 검토에서 보정 모델이나 UI를 바꾸지는 않았다.
특히 6점은 '다음 6점만 더 하면 완료'라는 일정 보장이 아니다.

## 후속 입력: 사용자 PD

- 사용자가 전체 PD를 64mm로 알려줬다. 사용자 제공 측정값이며 별도 실측 검증은 하지 않았다.
- 원거리/근거리 구분, 측정 방법/오차, 좌우 단안 PD는 아직 미확인이다.
  좌우가 각각 32mm라고 확정하지 않는다.
- 사용자가 기존 보정 중 Beast용 도수 렌즈를 착용했다고 확인했다.
  해당 렌즈 착용을 이번 보정의 조건으로 기록한다. 도수/처방전은 수집하지 않았다.
  이후 비교도 같은 렌즈 조건에서 진행하고, 렌즈 조건이 바뀌면 별도로 확인한다.
  이 확인만으로 기존 여섯 점을 폐기하거나 재수집하지 않으며, 도수 렌즈를 현재
  수치 불안정의 원인으로 단정하지 않는다.
- 향후 양안 모델 비교의 참고값으로 보존한다. 기존 독립 DLT의 가상 투영 중심 간
  거리를 64mm로 덮어쓰거나 현재 후보를 활성화하지 않는다.
- 기존 여섯 원본 pair 파일과 setup_id는 수정하지 않았다.
