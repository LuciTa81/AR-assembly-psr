# Beast 양안 모델 오프라인 비교 (2026-10-07)

## 결론

사용자 PD 64mm를 약한 참고값으로 사용하는 공통 양안 모델은 현재 여섯 관측에서
독립 DLT보다 작은 좌표 변화에 덜 민감했다. 그러나 한 자세를 제외한 예측에서
최대 약 80px 오차가 남으므로 **실물 정합 성공이나 활성화 가능한 보정으로 판단하지 않는다.**

사용자가 각 자세에서 편안하게 겹친다고 확인한 기록은 그대로 유효하다.
이번 결과는 그 점들을 연결해 새로운 자세를 예측하는 모델의 수치 진단이다.

## 구현 범위

- `server/realtime/display_joint_fit.py`: 비교 계산, 자세 단위 교차 검증, 가상 잡음 시험, CLI.
- `tests/realtime/test_display_joint_fit.py`: 합성 정답 복원, 소프트 PD, 잘못된 입력,
  검증점 분리, 양안 동시 제외, 재현성, 실패 집계, 원본 보존과 카메라 미접근 검사.
- `server/realtime/requirements-dev.txt`: 오프라인 계산용 SciPy 1.18.1 추가.
- 기존 `display_fit.py`, Unity, 런타임 설정, 인식/추적 임계값은 변경하지 않았다.
- 출력은 별도 `beast_joint_fit_comparison_v1` 보고서뿐이다. 실행용 프로필 export나
  활성화 옵션은 없고, 기존 probe exporter도 이 보고서를 거부한다.

## 계산 모델과 조건

두 눈은 공통 회전, 공통 fx/fy, 영 skew를 사용하고, 화면 중심 오프셋은 눈별로 추정한다.
눈 좌표계의 수평 baseline과 카메라 기준 중점 위치를 함께 추정한다. 총 13개 파라미터다.
독립 DLT는 눈별 11개, 총 22개 자유도다.

PD는 강제 고정하지 않는다. 목적함수는 화면 좌표 잔차를 2px로 나눈 항과
`(baseline_mm - 64) / prior_scale_mm` 항을 포함한다. 기본 scale은 5mm이며,
**2px와 5mm는 계산 가중치이지 실측 오차나 확률적 신뢰구간이 아니다.**
양의 깊이를 유도하는 항과 명시적인 파라미터 범위도 사용한다.
세 초기값에서 SciPy `least_squares`의 TRF, 선형 손실로 계산하고 모든 관측을 유지한다.

- PD 64mm는 사용자 제공값이다. 원거리/근거리 구분과 측정 오차는 미확인이다.
- 좌우 단안 PD를 각각 32mm로 확정하지 않는다. 모델 중점의 +/-baseline/2는 좌표 정의다.
- 기존 수집은 Beast용 도수 렌즈 착용, Extra Large / 4.5m, Full SBS / 0DoF 조건이다.
- 도수 렌즈의 광학 왜곡을 따로 추정하지 않는다. 렌즈가 문제 원인이라는 결론도 내리지 않는다.
- 공통 회전/초점거리 가정이 Beast 광학에 정확히 맞는지는 미검증이다.

## 실제 여섯 자세의 결과

명시적으로 선택했던 원본 pair 6개를 그대로 fit에 사용했다. 독립 check는 0개다.

| 항목 | 기존 독립 DLT | 공통 양안 후보, prior scale 5mm |
| --- | ---: | ---: |
| 왼눈 fit RMS | 1.475px | 2.319px |
| 오른눈 fit RMS | 2.201px | 2.915px |
| 전체 관측 중 최대 fit 오차 | 4.651px | 5.189px |
| 추정 두 중심 간 거리 | 97.409mm | 63.498mm |
| 독립 실측 check | 없음 | 없음 |

새 모델의 fit 오차는 약간 커졌다. 자유도가 줄었으므로 기존 점에 더 정확히 맞는다고
주장하지 않는다. 중심 거리가 64mm에 가까운 것은 PD 제약이 들어간 결과이며,
실측 PD나 광학 깊이가 독립적으로 검증됐다는 증거가 아니다. 기본 fit은 solver 경계에 닿지 않았다.

### 작은 좌표 변화에 대한 민감도

조건별 32회, 난수 seed 64. 두 모델에 동일한 가상 잡음을 넣어 다시 계산했다.
시험점은 기존 fit XYZ의 중심 `(-45.930, 98.913, 559.721)mm`이며 고정되어 있다.
아래 값은 각 모델의 원래 예측 대비 두 눈의 2D 이동량 RMS 중앙값이다.

| 가상 입력 변화 | DLT 예측 변화 | 공통 양안 예측 변화 |
| --- | ---: | ---: |
| 화면 좌표 각 축에 표준편차 1px 정규분포 잡음 | 4.618px | 0.605px |
| 카메라 XYZ 각 축에 표준편차 1mm 정규분포 잡음 | 17.144px | 1.656px |

각 조건/모델에서 32회 모두 계산됐다. 양안 저장은 하나의 3D 관측을 공유하므로
XYZ 잡음도 두 눈에 공통으로 적용했다. 원본 배열은 수정하지 않는다.

이는 **계산 민감도** 비교이지 실제 표시 정확도, 측정 잡음 분포 또는 신뢰구간이 아니다.
모델 제약이 강하면 편향이 있어도 덜 흔들릴 수 있다. 실제 렌더링 깜빡임을 측정한 것도 아니다.
기존 원인 검토의 13.94px 실험과는 시험점, 요약 통계, 시드, 횟수가 다르므로 직접 비교하지 않는다.

### 한 자세씩 빼고 예측

fit 6개에서 양안 한 쌍을 통째로 제외하고 남은 5개로 계산해 제외한 점을 예측했다.
별도로 지정된 check 점은 이 과정에도 사용하지 않는다.

| 제외한 자세 | 왼눈 예측 오차 | 오른눈 예측 오차 |
| --- | ---: | ---: |
| 1 | 14.51px | 18.22px |
| 2 | 1.89px | 2.96px |
| 3 | 3.95px | 6.80px |
| 4, 세로 위치가 다른 점 | 49.00px | 79.96px |
| 5 | 9.89px | 15.24px |
| 6 | 8.48px | 5.77px |

4번을 빼면 남은 카메라 Y 범위가 약 131mm에서 28mm로 줄어든다.
이 한 점에 대한 의존도가 높다는 정황이지, 4번 저장이 틀렸다는 판정은 아니다.
그 점을 삭제하거나 좋은 결과만 선택하지 않았다. 2/3번은 서로 가까운 자세다.

기존 DLT는 최소 6개가 필요하므로 5개를 이용한 같은 검증을 수행할 수 없다.
보고서는 6개 fold 전부 unavailable로 남긴다. 이 비교로 DLT의 교차 검증 오차가
더 크다고 주장하지 않는다. 교차 검증 자체도 새로운 실착용 확인을 대신하지 않는다.

## 다음 최소 단계

1. 원본 여섯 점, PD 참고값, 도수 렌즈/착용 조건과 이번 비교 결과를 보존한다.
2. 다음 착용 시 같은 렌즈/착용/화면 조건을 확인한다. 바뀌면 기존 set에 무조건 합치지 않는다.
3. 같은 정면 자세의 반복 대신 A가 시야 위쪽에 보이는 서로 다른 거리의 자세 2개를
   fit 보강 후보로 계획한다. 현재 세로 방향 의존도를 낮추기 위한 1차안이다.
4. 별도 자세 2개는 처음부터 check로 예약해 fit/가중치 선택에 섞지 않는다.
   개수만 채우면 성공한다는 보장은 없으며 예측 오차를 보고 다음 결정을 한다.
5. 결과가 충분하면 별도 승인된 시험용 연결에서 A 원만 짧게 자동 추적한다.
   양안 위치와 깊이 편안함을 확인한 뒤 B-D/연결선으로 넓힌다.

이번 단계에서는 추가 착용 시험, 카메라, Unity 실행을 하지 않았다.
새 모델 적용으로 화면 깜빡임이나 실제 정합이 개선됐다고 주장하지 않는다.

## 재현 및 검증

```powershell
python -m server.realtime.display_joint_fit `
  --dataset <selected-pairs-checkpoint.json> `
  --camera-profile <camera-candidate.json> `
  --workspace <workspace-candidate.json> `
  --pd-mm 64 --pd-prior-scale-mm 5 --perturbations 32 --seed 64
```

보고서는 기본적으로 `%LOCALAPPDATA%/ARAssembly/beast-mvp/display_fits/joint-<stamp>/report.json`에
새로 저장한다. 실행 디렉터리/원자료를 덮어쓰지 않는다.

- 기준 manifest: `display_correspondence/8b2e2a781c734de7aa1f5cc70b308f6f/selected-pairs-checkpoint.json`
- 최종 기본 비교: `display_fits/joint-20261007T090534Z-288d51b7/report.json`
- prior scale 2mm: `display_fits/joint-20261007T090535Z-400049e4/report.json`
- prior scale 10mm: `display_fits/joint-20261007T090537Z-7f314f47/report.json`
- 최초 계산 보고서 `joint-20261007T090227Z-5e8f2893`도 보존했다.
  최종 버전에는 교차 검증 위험을 상위 warnings에 노출했다. 기본 계산 수치는 동일하다.
- 원본 여섯 파일/manifest SHA-256과 기존 DLT 양안 행렬이 이전 보고서와 정확히 일치한다.
- 로컬 NumPy 2.5.3은 유지했고 SciPy 1.18.1만 추가했다.
- 새 비교 테스트 20개 통과. 전체 Python 테스트 446개 통과 (27.22초).
- Unity/C# 소스는 변경하지 않았고 이번 단계에서 Editor/Player나 실카메라를 실행하지 않았다.

관련 API: [SciPy least_squares 공식 문서](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html).

## 후속 사용자 보고: 착용 위치 불변 가정 재검토

최종 결과 안내 후 사용자는 수집 중 안경을 약간 올려 쓴 경우가 있었다고 보고했다.
현재는 어느 관측 전후인지, 횟수와 이동량이 얼마인지 확인되지 않았다.
시점을 물었을 때 사용자는 기억나지 않는다고 답했다. 따라서 저장 시각만으로
착용 변화 전후를 임의로 나누지 않으며, 이번 기록만으로 그 영향을 분리할 수 없다.
앞서 사용자가 안경을 벗지 않고 설정을 유지했다고 확인한 기록은 그대로 보존하되,
이 사실만으로 전체 수집 동안 눈과 안경의 상대 위치가 고정됐다고 간주하지 않는다.
기존 `setup_id`와 원본 파일은 수정하지 않으며, 같은 착용 조건의 데이터라는 가정은
현재 불확실한 것으로 취급한다. 이 세트는 진단 자료이며 보정 활성화 근거가 아니다.

머리와 안경이 함께 움직이는 경우와 안경이 얼굴 위에서 움직이는 경우는 다르다.
마커 추적은 카메라와 작업대 사이의 자세를 제공하지만, 현재 파이프라인은 눈과 안경
사이의 상대 위치 변화를 측정하지 않는다. PD 참고값 64mm는 이 상대 위치를 정하지 않는다.
각 시점에 수동 원을 편하게 맞췄더라도 서로 다른 착용 상태의 대응점을 하나의 고정된
눈별 투영으로 설명하기 어려울 수 있다. 이는 가능한 원인이지 이번 데이터의 확정 원인이 아니다.
관련 일차 연구: [Corneal-Imaging Calibration for Optical See-Through Head-Mounted Displays](https://pubmed.ncbi.nlm.nih.gov/26357098/).

저장 순서와 고정 모델의 잔차를 다시 대조했다. 마지막 check의 `예측 - 저장` 세로
잔차는 왼눈 +12.428px, 오른눈 +12.178px로 비슷하다. eye-local top-left 좌표에서
자동 예측이 저장 위치보다 아래에 있다는 뜻이다. 착용 변화와 양립하지만 모델 가정이나
카메라 목표 좌표의 편향도 가능한 설명이므로, 이를 안경을 올린 시점의 탐지 결과로 쓰지 않는다.
그 이전 fit들에는 가로 오차도 있어 전체 문제를 일정한 세로 오프셋 하나로 단정하지 않는다.

안경을 올린 시점을 알게 되면 기록 근거로만 관측을 구분한다. 오차가 작아지도록 임의로
시점을 골라 분리하거나 점을 삭제하지 않는다. 추가 검사는 별도 동의 후, 우선 동일 기준점에서
착용을 유지한 반복 관측과 착용을 조정한 관측을 카메라 자세와 함께 비교하는 짧은 원인
분리 시험으로 제한한다. 한 점의 보정만으로 전체 작업 공간을 해결했다고 주장하지 않는다.
이 검토에서는 카메라/Unity 실행, 새 수집, 코드 변경 또는 보정 활성화를 하지 않았다.

## 오프라인 좌표 경로 점검 및 자동 투영 재현

후속 진행 요청에 따라 원인 분리부터 수행했다. 이번 변경 범위는 공동 모델 보고서의

### 최소 코드 보강

- `server/realtime/display_joint_fit.py::_error`에 예측/저장 좌표와 signed residual을 추가했다.
  `common_shift_xy_px = (left_residual + right_residual) / 2`,
  `disparity_residual_xy_px = left_residual - right_residual`로 분리한다.
  기존 RMS/최대값, fit/check 구분, solver 및 경고 기준은 그대로다.
- Python 테스트 3개를 먼저 추가해 누락 필드로 실패하는 것을 확인한 후 구현했다.
  공통 이동과 양안 차이의 구분, 입력 불변성, pose 순서/관측 대응을 검사한다.
- `CandidateProjectionTests.OfflineReportMatchesActualProjectionCodeWithoutDeviceAccess`는
  로컬 보고서를 명시했을 때 실제 운영 `CandidateProjection.cs`의 `TryProject`를 호출한다.
  모델은 테스트 메모리에서만 사용하며 프로필을 내보내거나 장치를 열지 않는다.

### 짧은 2mm 안정 조건은 화면 정밀도 보장이 아니다

현 구현은 저장 직전 180~600ms의 3개 이상 프레임에서 A 좌표의 최대 두 점 거리가
2mm 이내인지 확인한다. 이는 해당 짧은 구간의 상대적인 변화량이고, 절대 오차나
눈별 조절 전체 시간 동안의 정합 안정성을 의미하지 않는다.

고정 투영행렬 P와 카메라 좌표 X에 대해 q=P[X,1], u=q[:2]/q[2]라 두면,
화면 좌표의 국소 미분은 J=(P[:2,:3]-u[:,None]*P[2,:3])/q[2]다.
두 최종 저장에서 카메라 세로 좌표 1mm 변화는 양안 세로 약 3.83px / 3.68px에 해당했다.
2mm 길이의 좌표 변화가 가장 민감한 방향으로 생긴다는 국소 근사에서는 눈별 약
7.7~8.2px 변화도 가능하다. 이는 실제로 그만큼 틀렸다는 주장이나 전역 오차 상한이 아니다.
해석적 J와 중앙 차분(0.001mm)의 최대 차이는 약 1.05e-10px/mm였다.

### 공통 세로 편향의 원인은 아직 미확정

첫/둘째 최종 정렬의 공통 세로 잔차 +10.98/+12.19px는 별도의 문제다.
국소적으로 카메라 세로 좌표를 약 -2.87/-3.32mm 바꾸면 이 잔차와 비슷한 크기의
화면 이동을 만들 수 있지만, 실제 좌표 오류가 그만큼이라는 뜻은 아니다.
같은 카메라 pose에서 목표의 world 높이를 가정상 5mm 늘렸을 때도 세로 위치는
약 -14.74/-14.34px 달라졌다. 이 역시 민감도 비교이며 60mm 등록 높이를 바꿀 근거는 아니다.

기존 단순 양안 모델에서 baseline만 1mm 늘리면 수평 좌표는 양눈 반대 방향으로
약 1.95/1.88px씩 변하고 수직 좌표 변화는 0이었다. 따라서 다른 변수를 고정한 PD/baseline
수정만으로 이번 공통 수직 잔차가 해결되지는 않는다. 실제 광학계 전체에 대한 증명은 아니다.
11~12px를 일괄 빼는 보정도 별도 검증 없이 적용하지 않는다.
