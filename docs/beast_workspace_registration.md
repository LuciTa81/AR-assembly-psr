# Beast 작업대 위치 등록

## 현재 범위

카메라 보정 + 실측 마커 중심 좌표로 작업대 자세를 계산하고, 알려진 높이의
나사 중심을 저장 사진에서 클릭하여 **후보 좌표**를 등록합니다.
기존 ROI, OnlineStateFilter, Unity 실행 설정에는 자동 적용하지 않습니다.
카메라 영상의 투영과 착용자의 눈/디스플레이 정합은 별개입니다.

초기 마커 프로필(2026-09-27): `configs/beast_workspace_metric_20260927.json`.
사용자 실측/행열 정렬 확인을 반영했습니다. 모든 단위는 mm입니다.

**2026-10-06 주의:** 실제 4/5번 마커를 옮겼으므로 아래 초기 프로필은 현재 배치에
사용하지 않습니다. 새 로컬 후보는
`%LOCALAPPDATA%/ARAssembly/beast-mvp/workspace_registration/comfort-layout-20261006-v1/workspace-candidate.json`입니다.
3번 원점과 0/1/2번을 유지한 상태에서, 사용자가 측정한 4->2 변위는
(오른쪽 335, 벽 쪽 110) mm, 5->2 변위는 (오른쪽 80, 벽 쪽 110) mm입니다.
따라서 새 4번 중심은 **[75,175,0]**, 5번은 **[330,175,0] mm**입니다.
이전 프로필과 원래 나사 등록 이력은 보존했습니다. 상자가 움직이지 않았다는
전제에서 A-D 좌표를 상속했으며, 독립 물리 정확도와 눈 정합은 아직 미검증입니다.

사용자가 편하다고 확인한 저장 사진 1장에서 등록 ID 0/1/2/4/5로 pose를 계산했습니다.
검출된 미등록 ID 17은 계산에서 제외했습니다. 초기 IPPE 계산은 RMS 3.191 px였고,
모호성 검사 후 LM 정밀 계산을 적용하자 RMS **2.576 px**, 최대 **4.211 px**였습니다.
기존 RMS 3 px / 최대 5 px 기준과 모호한 해 거부 규칙은 그대로 유지했습니다.
수치 계산의 일관성 검사이며 mm 정확도나 실시간 안정성 검증이 아닙니다.

진단 결과: `comfort-layout-20261006-v1/validation/projection-20261006T080524Z-d68d108d/`.
A/B는 사진의 나사머리 근처에 투영되지만 정답 픽셀 라벨로 오차를 측정하지 않았습니다.

저장하는 단계입니다. 기존 불편한 자세의 점을 새 정합 데이터로 재사용하지 않습니다.

마커 중심은 왜곡 보정 후 대각선 교점으로 구합니다. 기울어진 영상에서 네 코너의
산술평균을 물리 중심으로 쓰지 않습니다. 현재는 중심 4~6점을 사용하므로
24개 실측 모서리 기반 Board보다 관측 중복성이 적습니다.

## 1. 저장 사진의 작업대 자세 확인

현재 Beast Python 환경에서 프로젝트 루트를 기준으로 실행합니다.

```powershell
python -m server.realtime.workspace_registration --image "<원본 PNG>" --camera-profile "<candidate.json>" --workspace configs/beast_workspace_metric_20260927.json
```

기본 출력은 OneDrive 밖 `%LOCALAPPDATA%/ARAssembly/beast-mvp/workspace_registration/projection-<unique>/`입니다.
Codex 앱 가상화 환경에서는 Packages/OpenAI.Codex_.../LocalCache/Local 아래 실제 저장될 수 있습니다.

- `diagnostic.png`: 검출 마커와 예상 중심 십자, 등록된 경우 목표점.
- `report.json`: 원본/프로필 해시, 입력 해상도, pose, 각 점의 오차, 거부 사유.
- `camera-profile.json`, `workspace-profile.json`: 실행 입력 사본.
- 새 출력 디렉터리를 만들며 원본/이전 결과를 덮어쓰지 않습니다.
- `pose_estimated`는 물리 정확도나 눈 정합 합격을 뜻하지 않습니다.

초기 진단 문턱은 RMS 3 px, 개별 점 최대 5 px입니다(왜곡 보정 좌표).
평면 PnP 두 후보의 오차 차이가 0.25 px 미만이고 자세 차이가 2도 또는 위치 차이가
5 mm를 넘으면 모호한 것으로 거부합니다. 4개 미만 마커, 퇴화 배치, 해상도 불일치,
잘못된 입력은 거부하며 이전 pose를 대신 쓰지 않습니다.
이 수치들은 시험 시작값이며 실제 착용 허용 오차를 보장하지 않습니다.

## 2. 나사 위치 후보 등록

1. 상자/마커 위치를 유지하고 나사 4개의 머리가 거의 같은 높이인지 확인합니다.
   이미 뚜껑면 가까이에 있다면 추가로 강하게 조일 필요는 없습니다.
2. 매트에서 나사머리 윗면까지 실제 높이를 측정합니다.
   뚜껑면 높이와 머리 높이가 같다고 가정하지 않습니다.
3. 그 높이에 해당하는 사진을 사용합니다. 높이가 크게 다른 과거 사진에 한 높이를
   일괄 적용하지 않습니다. 근소한 차이를 허용한 초기 후보는 그 한계를 기록합니다.
4. 동일 높이의 나사머리 중심을 A, B, C, D 순서로 클릭하고 Enter로 확정합니다.
   A=먼 쪽 왼쪽, B=먼 쪽 오른쪽, C=가까운 쪽 왼쪽, D=가까운 쪽 오른쪽입니다.
   Backspace/우클릭은 마지막 점 취소, R은 초기화, Q/Esc는 저장 없이 종료입니다.

```powershell
# $headMm은 현재 사진 촬영 상태에서 직접 측정한 나사머리 높이입니다.
python -m server.realtime.workspace_registration --image "<새 원본 PNG>" --camera-profile "<candidate.json>" --workspace configs/beast_workspace_metric_20260927.json --pick-targets --pick-height-mm $headMm --target-height-mm 60
```

입력 사진에서 클릭한 머리 높이와 실제 안내할 뚜껑면 높이를 별도로 사용합니다.
카메라의 광선을 머리 높이 평면과 교차시켜 XY를 구하고, 안내점의 Z만 지정한
뚜껑면 높이(현재 사용자 근삿값 60 mm)로 설정합니다.
기울어진 나사, 서로 다른 머리 높이, 움직인 상자, 잘못된 카메라 보정에서는 이 가정이 깨집니다.

110 mm 정사각형의 네 변과 두 대각선이 클릭 결과와 맞는지 검사합니다.
작업대 XY 기준 A/C는 왼쪽, B/D는 오른쪽, A/B는 먼 쪽, C/D는 가까운 쪽인지도
검사하여 정사각형 형태를 유지한 채 라벨만 순환 이동한 클릭을 거부합니다.
허용 차이 10 mm는 잘못 클릭/높이/배치를 잡는 초기 sanity check일 뿐 정밀도 기준이 아닙니다.
점들을 완벽한 정사각형에 강제로 맞추지 않습니다. 후보에는 사진 해시, 클릭점,
입력 높이, 카메라/마커 프로필 출처를 저장합니다.

출력 `target-candidate.json`은 `not_activated`, `display_alignment_verified=false`입니다.
촬영에 사용하지 않은 자세/사진에서 네 목표 위치를 다시 확인한 뒤에만 다음 단계로 갑니다.
등록 사진에 다시 맞는 것은 독립 검증이 아닙니다.

## 3. 실시간 카메라 투영 진단

`workspace_live_preview.py`는 등록된 A-D를 **노트북의 원본 카메라 영상**에
그리는 별도 검사 도구입니다. 안경의 실제 물체 위 정합이나 Unity 연동이 아닙니다.
카메라 보정 ID/파일 해시가 등록 당시와 일치해야 시작합니다.

```powershell
python -m server.realtime.workspace_live_preview --camera-profile "<candidate.json>" --workspace "<target-candidate.json>" --camera 1 --duration 60 --save-every-seconds 5
```

카메라 인덱스는 현재 장치 목록/시점으로 확인하고 사용합니다. 상자와 마커는
옮기지 않습니다. Q/Esc 또는 창 닫기로 종료하며 최대 지정 시간 후 자동 종료합니다.
Space는 현재 프레임을 저장합니다. 자동 저장 옵션을 생략하면 자동 사진 저장은
하지 않으며, 수동/자동 합계 최대 12장입니다. 서버 전송이나 연속 영상 녹화는 없습니다.

- 매 프레임 마커로 pose를 새로 구하고 같은 원본 영상에만 목표를 그립니다.
- 마커 부족/퇴화/모호한 pose/진단 오차 초과 시 원을 숨깁니다. 이전 pose를 재사용하지 않습니다.
- 로컬 수신 후 150 ms를 넘으면 영상을 검게 바꾸고 원도 숨깁니다.
  이는 센서 노출부터 표시까지의 전체 지연 측정이 아닙니다.
- 캡처와 PnP는 별도 소유 프로세스에서 실행하여 카메라 호출이 멈춰도
  노트북 UI가 만료 처리를 할 수 있습니다. 종료 시 카메라를 해제하고,
  종료 요청에 응답하지 않는 해당 자식 프로세스만 종료합니다.
- `%LOCALAPPDATA%/ARAssembly/beast-mvp/workspace_registration/live-<unique>/`에
  프로필 사본/설정, 수신 프레임별 판정, 종료 요약을 기록합니다.
- 저장 사진에는 원본 `raw.png`, 표시본 `preview.png`, 당시 `report.json`이 있습니다.
  모든 결과는 `display_alignment_verified=false`, `physical_accuracy_verified=false`입니다.
- 촬영 중에는 판정과 최대 12장의 사진을 메모리에만 보관합니다. 창을 닫고
  카메라를 해제한 뒤 별도 저장 프로세스가 디스크에 기록합니다. 비정상 종료 시
  메모리 기록은 유실될 수 있습니다. 저장은 최대 10초 대기하며 실패/부분 저장을 보고합니다.
- Tk 진단 창을 사용하여 OpenCV 기본 창의 Ctrl+S 저장 대화상자로 인한
  만료 감시 중단을 피합니다. 카메라 오류는 영상 드롭 큐와 별도로 전달합니다.
- 저장 성공이 확인된 사진만 summary의 `sample_frame_ids`에 포함합니다.
  수신 중단으로 새 프레임이 없어도 stale 표시 전환을 별도 기록합니다.

착용 시험 순서: 정면 유지 -> 조금 왼쪽/오른쪽 -> 조금 가까이/멀리 ->
마커가 일부 가려진 시야 -> 정면 복귀. 급격하게 움직이거나 상자를 옮기지 않습니다.
다른 시점에서도 원이 나사머리를 따라가는지, 충분한 마커를 못 보면 사라지는지 확인합니다.

프레임 전달/만료/종료도 검사했습니다. 실기기 자세 변화 결과는 이후 별도로 기록합니다.

## 4. 나사 연결선과 목표 화살표 (2026-10-06)

기존 카메라 진단 창에 선택적인 `--assembly-overlay`를 추가했다.
등록된 나사 중심을 A-B-D-C-A 순서로 연결하고, 선택한 나사 위에 화살표를 표시한다.
화살표 끝은 나사보다 world Z 방향으로 8 mm 위, 꼬리는 30 mm 위다.
카메라 보정값과 현재 프레임 pose로 렌즈 왜곡을 포함해 투영한다.
이미지에서 단순히 픽셀을 위로 이동하거나 이전 pose를 유지하지 않는다.

이 선은 **나사 중심 사이의 윗면 연결선**이다. 11 cm는 나사 간격으로 사용했으며,
상자의 정확한 외곽선이나 전체 직육면체로 주장하지 않는다.
상자 또는 마커를 옮기면 등록 좌표를 다시 확인해야 한다.

### 실행

착용 준비 후 카메라 인덱스를 확인하고, 프로젝트 루트에서 실행한다.

```powershell
python -m server.realtime.workspace_live_preview --camera-profile "<camera-candidate.json>" --workspace "<workspace-candidate.json>" --camera 0 --duration 60 --assembly-overlay --target A --no-image-saving
```

- 창의 A/B/C/D 선택 또는 숫자 1/2/3/4로 진단 대상을 바꾼다. Q/Esc로 종료한다.
- `MANUAL TARGET`은 수동 시각화 대상이다. 인식 상태나 조립 단계는 바꾸지 않는다.
- 위 명령은 사진 저장을 금지하며 Space도 무시한다. 로컬 진단 JSON 기록은 남긴다.
- 기존 품질 거부와 150 ms 수신 만료 규칙을 유지한다. 유실 시 선과 화살표를 숨긴다.
- 화면 밖의 나사에 대한 화살표는 숨긴다. 연결선은 영상 경계에서 자른다.
- 이 옵션을 생략하면 기존 A-D 원 표시가 유지된다. Unity/상태 서버는 변경하지 않았다.

이미 촬영한 사진만으로 확인할 때는 다음과 같이 실행한다. 카메라는 열지 않는다.

```powershell
python -m server.realtime.workspace_live_preview --camera-profile "<camera-candidate.json>" --workspace "<workspace-candidate.json>" --image "<saved-photo.png>" --target A
```

OneDrive 밖 로컬 작업 폴더의 `overlay-still-<unique>/`에 `preview.png`와
`report.json`을 생성한다. 원본은 수정하지 않는다. 표시본은 `SAVED IMAGE`로
구분하며 프로필/원본 해시와 수동 목표를 기록한다. 사진의 수신 지연은 측정하지 않는다.

### 검증과 다음 단계

실제 저장 사진에서 ID 0/1/2/4/5로 pose가 추정되어 A/B 위치, 윗면 연결선과
A 화살표가 표시되는 것을 확인했다. C는 영상 밖, D는 하단 경계 근처였다.
이 결과는 정지 사진의 카메라 투영 확인이며 실시간 착용 정합이나 mm 정확도 검증이 아니다.

Python realtime 회귀 330개 통과. 새 검사에는 올바른 연결 순서, world-Z 높이,
pose 변화에 따른 재투영, 유실/만료/잘못된 pose 숨김, 화면 밖 대상 처리,
수동 선택 중 원본·인식 상태 보존, 같은 프레임의 목표 변경 재표시,
사진 저장 금지, 카메라 없는 파일 모드, 선 이음새 픽셀 회귀가 포함된다.
소프트웨어와 저장 사진 검증 중에는 카메라를 열지 않았다. 이후 동의받은 실입력
검사는 아래에 따로 기록한다. Unity 재빌드는 하지 않았다.

다음은 (1) 카메라 진단의 짧은 실시간 움직임 확인, (2) 눈별 보정 후보 검토와
별도 위치 검증, (3) 통과한 투영을 Unity SBS에 연결하는 순서다.
자동 목표는 기존 서버의 현재 작업 대상을 따르고, 접근만으로 다음 나사로 이동하지 않는다.
전체 직육면체 외곽선은 실제 외곽 치수와 원점을 확인한 뒤 확장한다.
Beast 화면 거리 설정의 Full SBS 경로 영향은 아직 확인하지 않았다.
보정 중에는 설정을 고정하고, 변경하면 기존 대응점의 유효성을 다시 확인한다.
