## 실행 구분

기존 `scripts/start_beast_assembly.ps1` 기본 동작은 바뀌지 않는다.
`-SourceRecoveryBoundary`를 붙이면 새 후보만 명시적으로 선택한다.
`-Live`가 없으면 검사만 하며 카메라/Unity를 실행하지 않는다.
새 옵션은 합성 UI 미리보기의 검증 범위가 아니므로 `-Preview`와 함께 사용할 수 없다.

실기는 별도 준비 확인 후 같은 착용/배치에서 A→D 한 번만 비교한다.
오버레이를 다시 맞추는 시험이 아니라 보류/복귀 흐름을 보는 시험이다.
실기에서 개선이 확인되기 전까지 성공본의 기본 옵션으로 승격하지 않는다.

## 가림 재현의 해석 제한

저장된 마커 모서리 좌표에서 ID 하나를 제거하는 검사는 이미 검출된 좌표의
부분 소실을 재현한다. 손에 의한 실제 가림, 흔들린 영상의 재검출,
렌더러 지연이나 사용자의 양안 융합을 재현하지는 않는다.
기존 마커 실패 구간에는 YOLO가 실행되지 않았거나 결과가 무효화된 경우가 있다.
그 구간의 pose 계산이 새로 통과하더라도, 없는 도구 증거를 만들어
단계가 더 빨리 끝난다고 계산해서는 안 된다.

새 pose의 재투영 오차가 작다는 사실과 기존 A~D 위치를 보존한다는 사실은 다르다.
전체 마커 계산과 마커 하나를 제거한 계산의 A~D 투영/카메라 좌표 차이를 함께 본다.
이는 물리 좌표의 독립적인 정답이나 눈별 광학 정확도가 아니다.

## 부분 가림 결과와 적용 결정

`server/realtime/partial_marker_replay.py`는 숫자 로그 전용이다.
정상 IPPE 경로를 그대로 반환하고, 정확히 네 등록 중심점이 충분히 퍼져 있으나
IPPE의 rank 조건을 만족하지 못할 때만 SQPNP 후보를 계산한다.
기존 물리 위치/모호성/재투영 RMS 3px/최대 5px 검사는 그대로 쓴다.
세 개 이하, 기존 품질 실패, 잘못된 입력은 이 후보로 우회하지 않는다.
실시간 서버에는 연결하지 않았다.

실제 C 940프레임의 기존 거절 이유를 모두 재현했다(불일치 0개).
geometry 거절 91개 중 90개에서 수치상 후보를 구했다.
통과 개수는 710→800이지만 **실물/양안 정확도나 표시율의 개선을 뜻하지 않는다.**

별도로 정상적인 다섯 마커 프레임 672개에서 마커 하나씩을 제거해
3,360개 사례를 비교했다. 아래 차이는 A~D 각각의 차이 중 가장 큰 값의
95백분위다. 화면 밖 목표도 제외하지 않았다.

| 제거 ID | 계산법 | 수치 통과/672 | 카메라 투영 차이 p95 | 목표 카메라 좌표 차이 p95 | 두 보존 조건 통과/672 |
| --- | --- | ---: | ---: | ---: | ---: |
| 0 | 기존 IPPE | 672 | 12.87px | 10.25mm | 4 |
| 1 | 기존 IPPE | 672 | 1.73px | 0.91mm | 672 |
| 2 | 기존 IPPE | 667 | 6.23px | 4.82mm | 513 |
| 4 | SQPNP 후보 | 665 | 7.83px | 5.52mm | 429 |
| 5 | SQPNP 후보 | 672 | 21.21px | 14.48mm | 0 |

보존 조건은 비교용 `<=5px AND <=5mm`이다. 임상/광학 합격 기준도,
실시간에 적용한 gate도 아니다. mm는 목표의 카메라 좌표 차이이며 실제 작업 오차가 아니다.
이 표는 마커 하나 소실의 영향이 ID와 배치에 따라 다르다는 근거다.
어떤 특정 마커의 측정이 틀렸다는 증거나 전체 마커 계산이 정답이라는 증거는 아니다.

따라서 이번에는 **복귀 경계 개선만 선택적 실기 후보로 준비**하고,
**가림 pose 후보는 오프라인에 유지**한다. 원의 TTL을 늘려 가림을 숨기거나,
기존 A~D 보정을 덮어쓰거나, 위치 보존이 불확실한 후보를 자동 적용하지 않는다.
