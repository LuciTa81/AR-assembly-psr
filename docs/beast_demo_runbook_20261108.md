# AR 조립 안내 시연 절차

## 시연에서 보여줄 것

안경에는 현재 나사 위치의 SBS 원과 작업 안내가 표시된다. 관제에는 작업대 영상,
현재 단계, 다음 행동, 보류 이유가 표시된다. 관제 영상은 카메라 시점이며 안경을 쓴
사람의 실제 양안 시야 녹화가 아니다.

흐름은 `상자 확인 → 뚜껑 확인 → A → B → C → D → 전체 최종 확인`이다.
상자·뚜껑·최종 상태는 사람이 확인한다. 나사 단계는 드라이버의 접근·유지·이탈을
관측해 자동 진행한다. 회전량·토크·실제 체결 완료를 자동 검증하는 시스템은 아니다.

## 실행

프로젝트 루트에서 PowerShell로 실행한다. 기존 로컬 Python, 보정 파일, Unity 빌드를
사용하며 다운로드·재빌드·보정값 교체는 하지 않는다.

```powershell
# 사전 점검만 한다. 카메라와 Unity는 켜지지 않는다.
.\scripts\start_beast_assembly.ps1

# 합성 입력으로 버튼과 화면 동선을 익힌다. 카메라·Unity 없음, 최대 1시간.
.\scripts\start_beast_assembly.ps1 -Preview

# 착용과 작업대 준비를 확인한 뒤 실제 시연. 기본 최대 5분.
.\scripts\start_beast_assembly.ps1 -Live
```

환경을 못 찾으면 `-Python '<기존 python.exe 경로>'`를 지정한다. 카메라 번호가 바뀌면
실제 Beast 입력을 확인한 후 `-CameraIndex`를 지정한다. 기본 번호는 0이며 재연결 후에도
항상 같은 카메라라는 뜻은 아니다. 점검 통과는 장치 연결·정합 정확도 검증을 뜻하지 않는다.

리허설은 실제 상태머신과 확인 API에 합성 증거를 넣는다. 상자·뚜껑 버튼을 누르면
A–D가 자동으로 흐른다. C에서 짧은 합성 추적 중단과 진행 보존이 한 번 발생한다.
최종 확인 뒤에는 완료 화면을 유지한다. 실제 성능 검증이나 시연 녹화로 사용하지 않는다.

## 준비

- Beast: Full SBS, 0DoF, Extra Large, 4.5m. Windows 확장과 3840×1080 출력 확인.
- 도수 렌즈와 착용 위치는 보정 때 조건을 유지한다. 중간에 안경을 올려 쓰면 정합을 다시 확인한다.
- 상자·마커를 고정하고, 실제 나사머리 높이를 등록 조건과 맞춘다. 카메라 렌즈 가림을 치운다.
- 검정·노랑 드라이버를 준비한다. 반복 시험에서는 이미 조인 나사를 더 조이지 않는다.
- 노트북 화면은 안경 카메라에 잡히지 않게 둔다. 관제 조작자와 안경 착용자를 나누면 편하다.
- 관제의 입력 종류와 현재 세션을 확인한다. 영상은 기본 꺼짐이며 필요할 때만 `영상 표시`를 켠다.

## 시연 동선

1. 관제 조작자가 상자 배치를 보고 `상자 완료 확인`을 한 번 누른다.
2. 뚜껑을 제자리에 닫은 뒤 `뚜껑 완료 확인`을 누른다.
3. 착용자는 A 원에 드라이버를 댄다. `HOLD` 동안 유지하고, 작업을 마친 뒤 `MOVE CLEAR`가 나오면
   카메라에는 드라이버가 보이게 나사에서 떨어뜨린다. B–D에서도 같은 순서로 진행한다.
4. 관제에서는 현재 목표·다음 행동·보류 이유를 설명한다. A–D에는 수동 넘기기 버튼이 없다.
5. 마지막에 네 나사와 뚜껑을 직접 확인하고 `전체 조립 최종 확인`을 누른다.
   완료 화면은 작업자의 최종 확인 기록이다.

혼자 조작할 때는 관제를 보느라 작업대 추적이 끊길 수 있다. 화면을 본 채 확인을 강제로
누르지 말고 작업대 추적 회복을 기다린다. 전시에서는 보조 조작자가 세 번의 확인을 맡는
방식이 가장 단순하다. 브라우저 기본 Tab/Enter 조작은 가능하지만 전역 단축키는 없다.

## 중단과 복귀

- `진행 보존 중`: 현재 나사의 관측 진행을 잠시 유지한다. 완료 판정이 아니며, 정상 입력으로 복귀해야 진행한다.
- `나사 X 재확인 필요`: 완료한 앞 단계는 유지하고 현재 나사를 다시 관측한다.
- 입력 지연·연결 끊김: 작업 지시는 보류된다. 영상이 남아 있더라도 최신 상태와 혼동하지 않는다.
- 반복 보류: 새 관제의 `연결·진단`에서 마커·도구·입력 나이를 확인한다. 기존 관제에서는 `입력 상세`를 연다. 조건을 낮추거나 수동으로 건너뛰지 않는다.
- 실제 시연은 Unity를 닫으면 이번 실행이 띄운 서버도 정리된다. 제한 시간 종료도 같은 방식이다.
- 서버를 새로 실행하면 새 세션으로 S0부터 시작한다. 프로세스 종료 뒤 진행 영구 복원은 아직 지원하지 않는다.
- 리허설은 실행한 PowerShell에서 Ctrl+C로 종료한다. 브라우저 탭만 닫으면 서버는 제한 시간까지 남는다.

## 안경과 관제의 용어

| 안경 표시 | 새 관제 표시 | 할 일 |
| --- | --- | --- |
| `WORK AT A` | 드라이버 접근 대기 | 표시된 나사에 드라이버를 댄다. |
| `HOLD AT A` | 드라이버 유지 중 | 작업 위치를 유지한다. |
| `MOVE CLEAR` | 드라이버를 떼어 주세요 | 작업을 마친 뒤 나사에서 떼되 카메라에는 보이게 유지한다. |
| `PAUSED - KEPT` | 잠시 멈춤 · 진행 보존 | 가림 등 표시된 보류 원인을 해소한다. 완료된 것은 아니다. |
| `RECHECK A` | 현재 나사 재확인 | 앞 단계는 유지되며, 현재 나사를 다시 관측한다. |
| `FINAL CHECK` | 마지막 확인 | 네 나사와 뚜껑을 직접 확인하고 최종 확인 버튼을 누른다. |
| `CONFIRMED` | 작업자 최종 확인 완료 | 작업자가 확인했음을 뜻한다. 자동 토크 검증이 아니다. |

위 표는 상태의 의미를 대응시킨 것이다. 공간 추적이 끊기면 안경은 원을 숨기고
별도의 마커 복귀 안내를 표시할 수 있다. 안경의 한국어 표시는 아직 적용하지 않았다.

## 장비 없는 동선 점검

리허설 화면에서 상자와 뚜껑이 준비된 상황으로 각각 확인 버튼을 누른다. A–D는
합성 입력으로 자동 진행하므로 드라이버를 움직이지 않는다. C에서 잠시 중단돼도
처음 단계로 돌아가지 않는지 보고, 마지막 확인 전과 후의 문구를 구분한다.
이 과정은 실제 장비의 인식·정합 성능 시험이 아니다.

처음 보는 사람에게 현재 대상과 다음 행동을 설명해 보게 하고, 중단 때 다시 시작해야
한다고 느끼는지, 최종 확인이 무엇을 증명한다고 이해했는지 묻는다. 도움을 요청한
지점과 오해를 기록한다. 이 사용자 관찰은 아직 수행하지 않았다.

## 발표 설명 예시

“카메라로 작업대와 드라이버를 관측하고, 현재 단계에 해당하는 나사 위치와 행동을
양안 AR로 안내합니다. 짧은 추적 중단에서는 관측 진행을 보존하고, 판단이 불확실하면
보류 이유를 표시합니다. 상자·뚜껑·최종 조립 상태는 사용자 확인으로 연결했습니다.
현재는 고정된 작업대와 보정 조건에서 검증한 시제품입니다.”

## 이번 변경 후 남은 실기 확인

새 관제의 실제 영상과 안경 안내를 함께 보면서, 세 번의 확인 버튼·A–D 자동 흐름·중단 시
보류 이유가 헷갈리지 않는지 한 번 확인한다. 이번 UI 작업만으로 정합 정확도나 자동 판정
성능이 개선됐다고 주장하지 않는다. 기존 성공본의 카메라·판정·Unity 코드는 변경하지 않았다.
