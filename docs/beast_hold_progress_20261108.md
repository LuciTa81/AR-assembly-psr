# 짧은 끊김의 진행 보존 안내

## 범위

기존 성공본의 단계 판정과 복구 시간은 바꾸지 않고, 서버가 실제로 기억하는 현재
나사의 HOLD 상태를 Unity와 관제에 표시한다. 구현 단계에서는 카메라를 실행하지 않고
합성 입력으로 Unity 창과 웹 화면만 검사했다. 이후 첫 A-B 착용 시험 결과는 아래에 기록한다.

| 서버 정보 | Unity 제목 | 관제 제목 |
|---|---|---|
| `retained` | `PAUSED - KEPT` | 진행 보존 중 · 잠시 대기 |
| `recheck` | `RECHECK A` 등 현재 목표 | 나사 A 재확인 필요 |
| `none` | 기존 안내 | 기존 안내 |

- `retained`: 현재 나사 관측이 복구 예산 안에 보존돼 있다. 완료·이탈 허가는 아니다.
- `recheck`: 현재 나사의 관측을 다시 확인해야 한다. 완료한 이전 단계는 되돌리지 않는다.
- 원인 설명은 유지한다. 복수 드라이버 후보라면 하나만 보여 달라는 안내가 계속 나온다.
- 새 메타데이터는 판정 결과를 읽기만 한다. 관측 시간, 이탈 확인, 단계 전환에는 입력되지 않는다.
- 정상 관측이 다시 시작되거나 단계가 바뀌면 재확인 표시를 해제한다.
- 짧은 보존 제목은 즉시 표시하지만, 아래 원인 설명은 기존 500ms 안정화를 유지한다.
  정상 안내 복귀의 250ms 안정화와 원의 숨김 조건도 그대로다.

## 만료와 호환

`AssemblyGuidance`에 `hold_progress`와 `hold_remaining_ms`를 추가했다.
남은 시간은 서버의 기존 부분/완료 HOLD 복구 예산에서 계산한다. 클라이언트는
서버 데이터 나이와 전체 요청 왕복 시간을 빼고, 중복 프레임으로 만료를 연장하지 않는다.
연결 끊김·오래된 상태·유효하지 않은 데이터는 진행 보존으로 표시하지 않는다.
예전 로그와 메시지에서 두 필드가 모두 없으면 기존 형식으로 처리한다.
새 로그에서는 두 필드를 포함해 정확 재생을 검사한다.

  짧은 표시를 실제로 알아보기 쉬운지는 확인되지 않았다.

## 다음 확인

즉시 반복 시험하지 않는다. 짧은 상태를 읽기 위해 현재 상태 표시를 거짓으로 늘리지 않고,
필요하면 별도의 과거형 복구 알림을 검토한다. 재확인 안내는 실제 해당 조건이 발생한
시험과 사용자 확인이 필요하다. 새 표시의 체감 효과나 실제 체결 검증을 주장하지 않는다.
