# C/D 추적 실패: 원인 구분과 좌표 가설

## 범위

카메라, Unity, 촬영, 실시간 설정 변경 없이 저장 숫자 로그만 분석했다.
기존 A~D 보정, 작업대 프로필, 인식 임계값, 진행 보존 시간은 그대로다.
새 모듈 `server/realtime/pose_failure_audit.py`는 오프라인 진단 전용이며 런타임에서 import하지 않는다.

대상은 2026-11-08 09:21 실기와 별도 00:17, 전날 23:28 성공 세션이다.
모든 입력의 카메라/작업대 프로필 연결, 프레임/캡처 시간, 저장 판정 재현을 검사했다.

## C: 세 중심점과 긴 소실

최신 C 구간은 총 392프레임이며 추적 실패는 48프레임이다.
639~671의 연속 실패 33프레임은 첫/마지막 캡처 간격이 3,199ms다.
처음에는 0/1/2/5가 보였고, 이어지는 32프레임에는 1/2/5만 보였다.
따라서 단일 마커의 300ms 소실을 보강하는 기존 후보로 해결할 수 없다.

640프레임의 세 중심으로 SQPNP를 계산하면 매트 위쪽에 있는 물리적 해가 두 개다.
둘 다 재투영 RMS가 약 1e-11px 이하이지만 카메라 위치는 크게 다르다.
이는 저장된 중심점만으로 해를 고르기 어렵다는 근거다. 세 마커를 쓰는 모든 추적이 불가능하다는 뜻은 아니다.
이 진단은 해의 개수와 좌표만 기록하고, 세 중심점 결과를 표시용 pose로 반환하지 않는다.
모서리 방향/실측 형상/시간 정보 등 추가 독립 제약이 필요하다.
영상 없이 손 가림과 시야 이탈 중 무엇이 원인인지 단정하지 않았다.

## D: 등록-관측 불일치

최신 D의 품질 실패 49프레임 모두에서 1번 중심의 잔차가 가장 컸다.
49개 중 24개는 다섯 마커, 25개는 0/1/4/5가 보이는 상황이다.
이는 1번이 반드시 잘못됐다는 증명이 아니다. 다른 등록 좌표나 카메라 내부 파라미터의 오차도 영향을 줄 수 있다.

### 채택하지 않은 방식

다섯 마커 중 잔차 5px 초과가 정확히 하나일 때 그 마커를 제외하고,
나머지 네 마커의 기존 IPPE/품질 검사를 적용하는 후보를 시험했다.
정상 결과는 그대로 반환하고 네 개 이하/복수 초과/모호한 해는 복구하지 않는다.

최신 D에서 15프레임을 추가 계산할 수 있었지만 오차 주입 시험에서는 실패했다.
정상 프레임을 30프레임 간격으로 택하고 각 마커를 영상의 상하좌우로 15px씩 옮겼다.
총 1,660개 상관 사례 중 후보 통과 319개, 원래 계산 대비 5px 및 5mm 이내 96개,
오차를 넣지 않은 마커를 잘못 제외한 경우 220개였다.
이것은 자연 가림의 실패율이 아니며, 자동 제외가 잘못된 위치를 만들 수 있다는 반례다.
이 방법은 실시간에 채택하지 않는다. 반례를 숫자 fixture와 테스트로 남겼다.

## 더 일관된 후보: 1번의 행 방향 좌표

다른 네 마커 0/2/4/5로 기존 품질 검사를 통과한 pose를 구한 뒤,
1번 관측 중심을 매트 평면으로 역투영했다. 이미 왜곡 보정된 중심을 다시 왜곡 보정하지 않는다.
이 좌표를 그대로 실측으로 취급하지 않고 기존 0~2 직선 위에 투영하여 1번의 가로 위치만 추정했다.
0/1/2가 같은 행이라는 기존 조건을 유지하므로, 작은 세로 오차로 공선 문제를 숨기지 않는다.

- 추정 자료: 최신 세션 S2~S5 중 프레임 800 이하, 사용 가능 252관측.
- 기존 1번: `[205, 285, 0]` mm.
- 오프라인 가설: `[202.0043548, 285, 0]` mm.
- 다른 마커, A~D 목표, 높이, 카메라/눈 보정은 추정하지 않았다.
- 이 값은 다른 좌표와 기존 카메라 보정에 종속된 가설이며 독립 실측값이 아니다.

### 추정에 사용하지 않은 자료와 비교

| 자료 | 평가 프레임 | 기존/후보 모두 통과 | 추가 통과 | 기존 통과 상실 | A~D 카메라 투영 변화 최대 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 최신 세션 801 이후 | 492 | 422 | 49 | 0 | 2.91px |
| 별도 00:17 세션 | 1,285 | 864 | 25 | 0 | 2.50px |
| 별도 전날 23:28 세션 | 1,508 | 1,123 | 14 | 0 | 2.69px |

평가 자료 3,285프레임에서 기존 정상 2,409개는 그대로 통과했고 추가 88개를 계산했다.
추가 통과 중 D는 각각 49/13/9개, 총 71개다. C의 긴 세 마커 소실은 해결하지 않는다.
위치 변화는 둘 다 통과한 프레임에서 기존 계산과 비교한 수치다.
추가 통과 프레임의 실제 위치 정답은 없으며, 실물 정확도/양안 편안함/작업시간 개선은 검증하지 않았다.
같은 장치/배치의 상관된 관측이며, 알고리즘 탐색 뒤의 별도 자료 비교이지 독립적인 최종 평가 실험은 아니다.

## 검증 및 적용 결정

- 전체 `tests/realtime` 회귀검사 847개 통과(56.92초).
- 신규 자동검사 28개 통과: 정상 경로 불변, 세 중심점 비출력, 잘못된 입력/프로필,
  원본 변경, 출력 덮어쓰기, 학습/평가 분리, 실제 실패 반례를 검사했다.
- 독립 검토에서 학습 파일 복사본의 평가 누수 P2를 발견했다.
  실패 테스트로 재현 후 경로뿐 아니라 내용 SHA256도 동일 trace로 판별하도록 수정했다.
- 등록 가설은 `calibration_valid=false`, `live_enabled=false`인 보고서만 저장했다.
  실행 가능한 작업대 프로필이나 기존 눈 보정 연결을 새로 만들지 않았다.

## 다음 최소 실기

1. 마커는 움직이지 말고 윗줄 0번 중심에서 1번 중심까지 행 방향 거리를 확인한다.
   기존 205mm와 가설 약 202mm의 차이를 확인하는 용도다. 대각선 거리와 혼동하지 않는다.
2. 실측/카메라 근거가 맞으면 별도 시험 프로필의 정상 연결 절차를 마련하고 카메라 투영부터 비교한다.
   프로필 해시가 바뀌므로 JSON 파일을 기존 눈 보정에 단순히 바꿔 끼우지 않는다.
3. A~D 위치 변화가 허용 가능한지 확인한 뒤 SBS 시험 여부를 결정한다. 기존 성공본은 유지한다.
4. C는 작업 자세에서 0/4가 함께 사라지는 원인을 미리보기로 구분한다.
   3초 넘게 가려진 구간을 오래된 pose나 가상의 도구 증거로 채우지 않는다.
