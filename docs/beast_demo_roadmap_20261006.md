# Beast 최소 시연과 후속 로드맵

최신 진행 상태와 다음 검증 순서는 [2026-10-07 오프라인 준비 상태](beast_offline_readiness_20261007.md)를 따른다.
아래 내용은 10월 6일 시연 준비 당시의 기록이다.

2026-10-06. 교수님 피드백을 위한 노트북 시연 화면부터 보강했다.
합성 시연, 실제 카메라 인식, 눈으로 보는 실물 정합은 서로 다른 검증 단계다.

## 현재 위치

| 항목 | 현재 확인 수준 |
| --- | --- |
| Python 입력·인식·기록 | 실행 가능. 현재 Beast는 camera index 0으로 확인했으나 재연결 시 다시 확인해야 한다. |
| Unity → Beast 안내 | 일반 2D 문구·단계 표시와 실입력 S1/S2 표시 확인. 이번에는 Unity를 변경하지 않았다. |
| S0~S6 상태 정책 | timed_v1 접근·이탈 정책과 합성 재생 구현. 현재 경로는 전체 시퀀스 Viterbi가 아니다. |
| 실제 나사 작업 | A 접근 OBSERVED는 확인. 이탈 중 마커·도구 관측이 끊겨 S2→S3 안정 통과는 아직 미확인. |
| 눈별 원 표시 | SBS 수동 단일 자세 정렬 확인. 자동 실물 정합·고개 이동·재착용 검증은 남아 있다. |
| 노트북 관제 | 상태·문구·단계·보류 이유와 선택적 원본 영상 구현. 별도 프레임 번호와 나이 표시. |

최근 사진 진단에서는 가까운 쪽 마커가 영상 하단에서 잘려 300프레임 모두
마커 0~3개였다. 현재 설정은 4개 이상 및 품질 0.25 이상이며 6개를 요구하지 않는다.
해당 품질은 homography inlier ratio로, 나사 위치 정합 정확도의 보증값이 아니다.

## 이번 구현

- [x] 기존 `supervisor.html`에 기본 OFF인 영상 표시 스위치 추가.
- [x] 마커 추적 유실과 원본 영상 수신을 분리. 추적이 끊겨도 새 영상은 계속 보인다.
- [x] 영상 자체가 멈추면 마지막 영상을 유지하고 갱신 중단으로 표시.
- [x] 기존 서버 phase로 대상 접근 / 접근 관측 / 이탈 대기를 표시.
- [x] 마커 추적, 새 분석 대기, 도구 미검출·복수 검출, 끝점 미확인 등의 보류 이유 표시.
- [x] S6는 사용자 최종 확인 대기. 체결 완료나 토크 검증으로 표시하지 않음.
- [x] 카메라 없는 합성 작업대·안내 반복 시연 제공.

좌표 없는 원본 영상 위에 나사 원이나 YOLO 박스를 임의로 붙이지 않았다.
현재 영상과 상태는 별도 HTTP 요청으로 받으므로 동시 프레임이라고 주장하지 않는다.
안내 데이터 유효 시간은 기존 500 ms, 영상 미리보기의 갱신 판단은 별도 1500 ms다.
영상의 프레임 번호·시각은 JPEG와 같은 잠금 구간에서 읽는다. 반복 프레임은 수명을 연장하지 않는다.
브라우저는 조립 상태를 별도로 추론하거나 서버 상태를 변경하지 않는다.

## 바로 보여줄 화면

실제 서버 실행 시:
`http://127.0.0.1:8765/supervisor.html`

이번 합성 시연:
`http://127.0.0.1:18765/supervisor.html`

영상 표시를 켜면 합성 작업대가 나타난다. 실제 카메라·검출 모델은 실행하지 않으며
사진도 사용하지 않는다. 상태는 기존 실제 필터에 합성 관측값을 넣어 생성한
R4 fixture다. 작업대 그림은 설명용 모식도이지 카메라 영상이 아니다.
24초 흐름을 반복하고 실행 후 30분에 자동 종료한다.

재실행은 프로젝트 루트에서:

```powershell
& "$env:USERPROFILE\AppData\Local\ARAssembly\beast-mvp\.venv\Scripts\python.exe" -X utf8 -B tests/unity/serve_snapshot_fixture.py --supervisor-demo --port 18765 --seconds 1800
```

18765는 실제 Unity 서버의 8765와 분리했다. 이번 합성 시연을 Beast로 자동 송출하지 않는다.
새 서버 임대, AWS, Laravel, 운영 SafeOps 연결, 추가 유료 서비스는 사용하지 않았다.

## 교수님께 보여줄 순서

1. 실제 입력 사진으로 카메라 시야와 마커 잘림 문제를 설명한다.
2. 합성 표시를 명확히 밝히고 S2의 접근 관측 → 도구 이탈 대기 → S3 흐름을 보여준다.
3. 추적이 끊겼을 때 단계 안내가 보류되는 화면을 보여준다.
4. 실제 카메라 인식은 S2와 A 접근 관측까지 확인했고, 이탈 안정화와 눈별 정합은 남았다고 구분한다.

설명 예시:
“기존 인식 서버의 결과를 안경 안내와 관제에서 공유하도록 구성했습니다.
현재는 관측 상태와 중단 이유를 확인할 수 있는 단계이며,
실제 작업의 이탈 판정과 실물 위의 정합 정확도를 다음 단계에서 검증합니다.”

피드백 질문은 ‘접근 관측/이탈 대기 구분이 작업자에게 이해되는가’,
‘실물 정합의 허용 오차와 작업 범위를 어느 수준으로 잡을 것인가’에 집중한다.

## 다음 순서

| 순서 | 할 일 | 확인할 결과 |
| --- | --- | --- |
| 1. 시야·분석 위치 | 편한 착용 자세에서 마커 테두리·흰 여백이 온전히 보이는 구도 확보. 정상 추적일 때 기존 A–D 분석 위치와 실제 나사 비교 | 마커 4개 이상에서 추적 유지. 카메라 위 분석 위치를 사진으로 확인. 눈별 정합 성공으로 대체하지 않음 |
| 2. 전이 안정화 | 실제 드라이버 끝점·중복 검출 및 접근 후 이탈 과정 진단. 필요 시 짧은 관측 유실의 접근 이력 유지 방식을 별도로 설계 | 손 스침에는 유지, A 작업 중에는 A 유지, 유효한 이탈 뒤에만 B 안내. 미검출·마커 유실만으로 전이 금지 |
| 3. Beast 실물 정합 | 기존 눈별 수집·보정·SBS 구현 재사용. 여러 대응점으로 보정하고 보정에 쓰지 않은 위치에서 확인 | 정한 작업 거리·자세에서 실제 나사와 원의 오차 측정. 고개 이동·가림·재착용 확인 |
| 4. 최종 반복 평가 | 별도 조립 실행 3회 이상과 실패 사례 기록 | 조기 전이, 전이 지연, 추적 유효율, 정합 오차를 나눠 보고. 실행 자료와 한계 정리 |

현재 핵심은 원격 인프라 확장이 아니라 1→2→3의 실제 동작이다.
다른 장소에서 관제가 꼭 필요해질 때에만 인증을 갖춘 읽기 전용 원격 공유를
검토하고, 로컬 인식·안경 안내를 클라우드 응답에 의존시키지 않는다.

## 후속 진행: 시각적 공간 피드백

앞선 마커 잘림 진단 이후 편한 자세에 맞춰 ID 4/5의 배치를 바꾸고 좌표 후보를
등록했다. SBS 눈별 수동 정렬과 다른 자세의 대응점을 수집했으나 아직 자동
눈별 보정 프로필로 활성화하지 않았다. 사용자는 가까운 자세에서 원이 나사보다
깊게 보인다고 보고했다. 화면 거리 설정을 해결책으로 확정하거나 나사 높이를
임의로 바꿔 보상하지 않는다.

- 구현: 카메라 진단에 나사 중심 윗면 연결선과 수동 선택 목표 화살표 추가.
- 확인: 기존 저장 사진에서 투영 확인, Python realtime 330개 통과.
- 추가 확인: 동의받은 30초 카메라 검사에서 163프레임 투영, 거부 112프레임 숨김.
  사진/영상 저장 없이 정상 종료했다. 마커 중복·시야 유실로 표시 연속성은 아직 부족하다.
- 다음: 추적 연속성 원인 확인과 눈별 정합 보정·별도 위치 검증 → Unity SBS 연결.
- 그다음: 서버의 현재 작업 대상과 연결. 실제 외곽 치수 확인 후 직육면체 표현 확장.

실행 방법과 제한은 `beast_workspace_registration.md`의 4절을 따른다.
현재 교수님께 보여줄 사진에는 `SAVED IMAGE / CAMERA ONLY / MANUAL TARGET`이
표시된다. 자동 인식 기반 실물 정합을 완료한 화면으로 소개하지 않는다.
