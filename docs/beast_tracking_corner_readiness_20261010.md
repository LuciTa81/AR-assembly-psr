## 모서리 방식의 가능성과 미확인 조건

기존 합성 fixture `tests/realtime/test_workspace_projection.py::models`에 있는
정확한 70mm 정사각형 모서리를 사용해 IPPE를 오프라인으로 계산했다.
각 중심에 `(-35,35,0),(35,35,0),(35,-35,0),(-35,-35,0)`를 더한 점들을
검출 순서에 대응하고, 픽셀 왜곡을 제거한 뒤 solvePnPGeneric(IPPE)에 전달했다.

| 합성 장면의 마커 | 대응 모서리 수 | 기하 제약 / 계산 |
| --- | ---: | --- |
| 0,1,2 | 12 | 기하 검사 통과, 참값 복원 |
| 0,1,2,4 | 16 | 기하 검사 통과, 참값 복원 |
| 0,2 | 8 | 기하 검사 통과, 참값 복원 |

세 경우 모두 무잡음 합성 재투영 RMS < 0.000001px,
카메라 위치 오차 < 0.000001mm였다. 이상적인 입력의 수학적 확인일 뿐,
실제 종이 마커/Beast의 정확도나 두 마커만으로 충분하다는 증거가 아니다.
중심점 세 개가 일직선이어도 정사각형의 모서리 전체는 일직선이 아니라는 점을 확인했다.

실제 작업대에서 아직 필요한 정보:

1. 흰 종이가 아닌 검은 외곽의 정확한 한 변. 현재 약 70mm라는 근삿값만 있다.
2. ID별 검출 모서리 0~3과 작업대 방향의 대응. 종이의 회전 방향을 모두 같다고 가정하지 않는다.
3. 최신 중심 실측값과 평평한 부착 상태. 모서리 기반 계산은 종이 휨과 배치 오차에도 영향을 받는다.

중심 실측값과 변 길이, 회전이 확인되면 24개 모서리를 전부 자로 재는 대신
각 마커의 네 세계좌표를 생성할 수 있다. 기존 사진에서 추정한 방향은 후보로만 보관한다.
기존 pose를 역투영해 얻은 모서리로 같은 pose를 재계산한 결과를 독립 검증이라고 주장하지 않는다.

## 최소 후속 순서

1. **오프라인 후보**: 기존 중심 프로필을 보존하고 별도 명시적 모서리 좌표 후보를 만든다.
   `workspace_projection.py`의 현재 계산은 유지하고, 실제 코너 순서/왜곡/물리 조건/모호성에
   대한 회귀 검사를 먼저 둔다. 후보 계산은 저장 로그에서만 비교한다.
2. **동일 기록 비교**: 0개 검출은 복구 대상에서 제외한다. 0,1,2 및 0,1,2,4/5 조합과
   기존 정상 조합을 나눠 가용성, 재투영 오차, 자세 점프를 비교한다. 개선율을 미리 약속하지 않는다.
3. **조건부 실행 연결**: 먼저 알려진 실측 배치에서 최소 3마커/12모서리를 후보 시작 범위로 검토한다.
   이는 채택 완료된 기준이 아니다. 현재 서버 관측과 Unity 수집 검증에도 최소 4마커 조건이
   있으므로 solver 숫자만 낮추지 않는다. 후보 프로필/관측 계약과 소비자 검증을 함께 다룬다.
4. **짧은 착용 검증**: 충분히 안정적인 관측이 확보된 다음에만 같은 착용에서 A 기준점과
   보정에 쓰지 않은 자세를 확인한다. 고개 이동과 안경을 올려 쓰는 변화를 구분한다.
5. **양안 정합과 확장**: 카메라 추적과 별도로 눈별 투영 오차를 확인한 뒤 B-D/연결선으로 확장한다.

Point2Pose 전체 도입, RGB-D/서버 추가, optical flow, IMU 융합, 오래된 원 계속 표시,
인식 임계값 완화는 이번 변경에 없다. 실제 이미지가 없는 수치 trace로 optical flow를
검증할 수는 없으며, 추적 개선이 눈-디스플레이 보정을 대신하지 않는다.

## 1차 오프라인 후보 구현 (2026-10-10)

`workspace_projection.estimate_corner_pose`를 추가했다. 새 서버, SDK, UI, 의존성은 없다.
실제 보정 프로필을 읽거나 활성화하지 않는 순수 계산 함수이며, 실시간 호출부도 연결하지 않았다.

- 입력: 현재 프레임의 검출 모서리, ID별 명시적인 `(4,3)` 세계좌표(mm),
  기존 CameraModel, 실제 영상 크기. 영상 파일이나 카메라 핸들은 입력하지 않는다.
- 세계좌표는 기존 X-right/Y-away/Z-up 체계의 Z=0 평면이며,
  마커마다 검출된 0~3번 모서리와 같은 순서여야 한다. 화면상 왼쪽 위부터 다시 정렬하지 않는다.
  종이가 회전한 각도와 검출 첫 모서리의 위치를 임의로 가정하지 않는다.
- 후보는 최소 3개 등록 마커의 12개 모서리를 요구한다. 중심 좌표만 주면 거절한다.
  한두 개 마커로 자동 전환하거나 모르는 ID를 새로 등록하지 않는다.
- 기존 왜곡 보정과 IPPE/LM 계산, 매트 위 카메라/양의 깊이 확인, 모호성 거절,
  기본 3px RMS/5px 최대 오차 검사를 공유한다. 오류 시 이전 pose를 대신 반환하지 않는다.
- 결과형 `CornerPoseCandidate`의 잔차는 모든 모서리에 대한 값이다.
  기존 `WorkspacePose`의 중심점 잔차 필드로 위장해 내보내지 않는다.
- 기존 `estimate_pose`의 4마커 중심 방식, 관측 응답 및 Unity 4마커 검증은 그대로다.

일반 합성 장면에서 0/1/2, 0/1/2/4, 0/2/4/5 조합과 ID별 서로 다른 회전을 검증했다.
알려진 카메라 위치/자세와 높이 60mm 나사 A의 투영을 복원하는지 확인했다.
이는 계산 함수의 검증이며, 실제 마커 치수가 맞거나 안경 정합이 개선됐다는 뜻은 아니다.

추가로 OpenCV 4.14.0이 특정 대칭 합성 자세에서 IPPE 후보를 NaN으로 반환하는
사례를 재현했다. 왜곡 제거 픽셀과 이상적 픽셀의 차이는 약 2.3e-9px였지만,
이상적 픽셀 또는 역순 대응점에서는 유한한 결과를 반환했다.
원인을 특정 OpenCV 내부 수식으로 단정하지 않으며, 임의의 픽셀 이동이나
대체 solver로 통과시키지 않았다. 이 사례는 정확한 pose 또는 명시적 nonfinite 거절만
허용하는 회귀 검사에 남겼다. 따라서 모서리 방식도 모든 자세에서 추적을 보장하지 않는다.
