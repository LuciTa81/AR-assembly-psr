# 짧은 마커 가림: 추가 오프라인 조사

## 결론

기존 A~D 보정, 성공 설정, 실시간 서버, Unity 표시 경로는 변경하지 않았다.
카메라/Unity 실행, 촬영, 외부 업로드도 하지 않았다.

짧은 가림을 위한 **과거 정상 프레임 기반의 새 오프라인 후보**를 구현했다.
5번 마커 소실에서 단순 SQPNP 대체보다 기존 위치를 보존하는 사례가 늘었다.
그러나 4번 소실에서는 일관된 우위가 없고, 일부 큰 위치 변화가 남는다.
**현재 실시간 적용은 하지 않는다. 실물/양안 정합이 검증됐다는 뜻도 아니다.**

## 확인한 것

1. 기존 중심점 방식은 세 중심이 공선인 네 마커 조합을 거절한다.
2. 단순 SQPNP는 그 조합도 계산하지만, 현재 등록 좌표의 작은 오차에 민감하다.
3. 일부 연속 프레임에서 모서리 폭이 달라지는 동안 중심은 비교적 유지된다.
   이는 모서리 전체를 그대로 추적 근거로 쓰기 어렵다는 관측이다.
   영상 없이 경계 선택/조명/블러 중 무엇이 원인인지 확정하지 않았다.
4. 과거 정상 프레임의 중심 관계를 임시 참조로 쓰면 5번 소실의 체계적인 위치 변화가 줄었다.

모서리 전체 참조, RANSAC 모서리 선택, 모서리 교차 확인도 개발 구간에서 탐색했다.
통과율 또는 최악 위치 변화에서 명확한 우위가 없어 런타임 코드로 확장하지 않았다.
그 탐색 결과는 아래 정식 검증 통계에 포함하지 않는다.

## 구현 범위

새 파일: `server/realtime/temporal_marker_replay.py`

- 정상 다섯 마커 pose에서 관측 중심을 매트 평면으로 역투영한다.
- 이 임시 중심 관계는 독립 실측값이나 새 보정 파일이 아니다. 기존 프로필에 저장하지 않는다.
- 현재 네 마커가 기존 방식의 geometry 검사에서만 실패할 때 SQPNP로 다시 계산한다.
- 이전 pose를 현재 pose로 내보내지 않는다. 현재 프레임의 중심 관측이 반드시 필요하다.
- 정상 경로는 기존 결과 객체를 그대로 반환한다.
- 3개 이하, 품질 실패, 다른 ID, 해상도 불일치 등은 우회하지 않는다.
- 참조 사용 기간은 마지막 정상 다섯 마커 캡처부터 최대 300ms다.
- 부분 가림 결과로 참조를 갱신하거나 기한을 연장하지 않는다.
- 기존 물리 위치/모호성/RMS 3px/최대 5px 검사와 참조 대비 5도/30mm 한계를 적용한다.
- 임시 참조 생성 실패는 참조만 폐기한다. 이미 통과한 정상 pose는 유지한다.
- 서버/Unity의 입력 만료 150ms, 작업 증거 보존 시간, 단계 조건은 수정하지 않았다.

300ms는 과거 참조의 사용 한계다. 현재 pose를 300ms 동안 화면에 붙잡아 두는 TTL이 아니다.
실시간 연결은 없으며 이 모듈은 정상 서버 경로에서 import되지 않는다.

## 평가 구분

개발 구간: 최신 성공 세션 C의 722~1191 프레임.
평가 구간: 같은 세션 1192~1661, 별도 성공 세션 001713 및 232856.
카메라/작업대 프로필 해시가 모두 같은 자료만 사용했다.

8프레임 블록마다 첫 프레임을 참조로 삼고, 이후 1/3/5프레임 동안 ID 하나를 제거했다.
가려진 프레임의 원래 다섯 마커 pose는 비교 정답 역할로만 사용했다.
이를 후보 계산이나 참조 갱신에 전달하지 않았다.
프레임 복귀 후에는 기존 정상 경로로 돌아가는지도 확인했다.

총 4,388개 원본 프레임, 12,235개 마커 제거 사례를 검사했다.
마커 ID와 가림 길이를 바꾸면서 같은 관측을 여러 번 사용하므로 독립 실험 수가 아니다.
원본 pose 판정 재현 불일치는 0개, 복귀 사례 4,205개는 모두 기존 정상 결과를 반환했다.

## 결과

### 실제 저장 구간

| 구간 | 전체 프레임 | 기존 정상 pose | 추가 임시 후보 |
| --- | ---: | ---: | ---: |
| C 개발 구간 | 470 | 351 | 22 |
| C 평가 구간 | 470 | 359 | 19 |
| 별도 세션 001713 | 1,528 | 905 | 12 |
| 별도 세션 232856 | 1,920 | 1,141 | 15 |

C 전체에서는 계산 가능 프레임이 710→751로 늘었다.
실제 소실 프레임의 정답 pose는 없으므로 이 41개가 정확하다고 판정한 것이 아니다.
카메라 표시율, Unity 표시율, 작업시간 개선으로 해석해서도 안 된다.

### 평가 구간의 3프레임 제거

위치 보존은 원래 다섯 마커 계산 대비 A~D 최대 변화가
카메라 영상 5px 이하 **그리고** 카메라 좌표 5mm 이하인 경우다.
5mm는 실제 나사와의 오차나 눈의 정합 오차가 아니다.

| 소실 ID | 사례 | 임시 후보 통과 | 위치 보존 | 후보 투영 차이 p95 / 최대 |
| --- | ---: | ---: | ---: | ---: |
| 4 | 741 | 563 | 445 | 7.90 / 11.60px |
| 5 | 741 | 563 | 492 | 7.04 / 11.16px |

후보가 없는 나머지 사례는 참조 시간 만료 등으로 숨긴다.
통과한 후보 안에서도 각각 118개/71개가 두 보존 기준 중 하나를 넘었다.
단순 SQPNP 비교 후보의 위치 보존은 같은 741개 중 ID 4에서 492개,
ID 5에서 1개였다. 시간 참조가 없는 비교법과 사용 가능 구간은 다르다.
따라서 새 방식이 모든 ID에서 무조건 더 낫다고 주장하지 않는다.

## 검증과 유지보수

- `pytest -q tests/realtime -p no:cacheprovider`: 최종 819개 통과, 68.17초.
- 신규 자동검사 29개: 미래 관측 누수, 참조 만료, 중복/역순 입력, 잘못된 프로필,
  오래 가림, 큰 움직임, 원본 파일 변경, 출력 덮어쓰기 금지 등을 확인했다.
- 실제 C의 12프레임 숫자 fixture를 추가했다. 사진/영상은 포함하지 않는다.
- 독립 검토의 정상 경로 예외 전파 P2를 실패 테스트로 재현한 뒤 수정했다.
- 후보 자체는 실시간 단계 판정에 연결하지 않았다. 없는 YOLO 증거를 만들어내지 않는다.

결과 디렉터리: `outputs/short_occlusion_20261108/final/`
집계: `summary.json`
실제 로그 회귀 fixture: `tests/fixtures/short_occlusion_20261108.json`

## 일어난 뒤 순서

1. 기존 성공본으로 화면/작업대 입력만 확인한다. 눈 보정을 다시 수집하지 않는다.
2. 이미 준비한 `-SourceRecoveryBoundary` 옵션으로 A~D 보류/복귀 흐름을 비교한다.
3. 가림 후보는 별도 카메라 투영 진단에 연결할지 먼저 결정한다.
   첫 대상은 근거가 더 좋은 5번의 짧은 소실로 제한하고, 작업 단계 자동 진행은 분리한다.
4. 카메라에서 위치 유지가 확인된 뒤에만 SBS로 비교한다.
5. 원이 뛰거나 편하지 않으면 기존 성공본을 유지한다. 시간 제한/임계값을 임의로 풀지 않는다.

## 시연과 팜플렛 표현

현재 확인된 것은 상자/뚜껑 사용자 확인, A~D 도구 접근·유지·이탈에 따른 안내,
마지막 사용자 완료 확인까지의 통합 흐름이다.
짧은 가림 후보는 개선 연구로 구분하며, 가림에 강한 정합이 완성됐다고 쓰지 않는다.
나사 조임 토크/완전 체결을 자동 검증한다고도 쓰지 않는다.
기존 성공본의 설명과 자료 준비는 이 후보의 채택 여부와 분리해 진행할 수 있다.
