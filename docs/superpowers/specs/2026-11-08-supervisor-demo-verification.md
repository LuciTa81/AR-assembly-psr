# 관제 화면 후보 검증 및 시연 동선

## 변경 범위

`web_overlay/supervisor_demo.html`, `supervisor_demo.css`, `supervisor_demo.js`만 새 관제 구현이다. 기존 `supervisor.js`, `supervisor_state.js`, `supervisor_video.js`의 상태 수신, 확인 API, 영상 opt-in 동작을 그대로 사용한다. 원래 관제 페이지, A-D 보정, Unity, 인식 임계값, FSM, 서버 API는 수정하지 않았다.

## 화면

- 넓은 작업대 영상, 현재 목표와 다음 행동, 접근/유지/이탈 상태, 전체 순서.
- 진행 보존, 재확인, 연결 끊김, 최종 확인을 별도 문구와 색상으로 구분.
- 목표 도식은 작업자 기준 A/B가 먼 쪽, C/D가 가까운 쪽이다. 실측 영상 투영이 아니다.
- 최근 흐름은 이 페이지가 수신한 주요 변화 최대 12개이며 새 세션에서 지워진다. 기존 서버 로그를 대체하지 않는다.
- 영상은 기본 꺼짐. 기존 관제와 카메라 진단으로 이동 가능. 작은 화면에서는 행동 안내가 먼저 표시된다.

## 검증

1. Node 테스트 45개 통과. 저장 성공 세션의 상태 의미 재생도 포함한다.
2. 브라우저 검사: 5개 화면 크기(320, 390, 1280, 1440, 1920px) x 9개 상태. 가로 넘침, 주요 문구 잘림, 페이지 JavaScript 오류 없음.
3. 확인 버튼 중복 입력 방지, 연결 중단 시 작업 지시 보류, 영상 기본 off 및 off 후 요청 중지, 키보드 이동, 전체 화면, pagehide/pageshow 복귀 확인.
4. 실제 `AssemblySession`과 HTTP 확인 API에 합성 입력을 넣어 상자/뚜껑/최종의 세 번 확인과 A-D 자동 진행 완료.
5. 별도 검토에서 발견한 자동/수동 모드 문구 오류를 회귀 테스트로 고쳤다. 추가로 화면 전환 시 도식 갱신 지연과 브라우저 캐시 복귀 문제를 재현 후 수정했다.

## 시연 동선

1. 기존 실행 절차로 서버를 켠 뒤 같은 서버의 `/supervisor_demo.html`에 접속한다. 기존 화면은 `/supervisor.html`로 계속 사용할 수 있다.
2. 운영자는 입력 종류와 연결 상태를 확인하고 필요할 때 영상 표시를 켠다.
3. 착용자는 작업대를 보고, 운영자가 상자 배치와 뚜껑 닫힘을 각각 확인한다.
4. A-D는 안경의 HOLD/MOVE CLEAR 안내에 따라 작업한다. 운영자는 보류 이유만 확인하고 임의로 단계를 넘기지 않는다.
5. 실제 조립 상태를 작업자가 확인한 후 운영자가 최종 확인한다.

착용자가 혼자 노트북을 바라보는 동안 추적이 끊길 수 있는 기존 제약은 남아 있다. 이번 변경은 핸즈프리 조작이나 자동 체결 검증을 추가하지 않는다. 실제 안경과 연결해 한 차례 시연한 후 새 관제를 기본으로 채택할지 결정한다.

## 남은 확인

- 실제 카메라와 Unity 연결 상태에서 가독성 및 관제 동선 확인.
- C/D 근거리 정합과 가림 성능은 기존 후보 상태 그대로이며 이번 UI 검사로 검증된 것이 아니다.
- 도구 접근/유지/이탈 관측은 토크 또는 완전 체결 검증이 아니다.
- 팜플렛/포스터 캡처에는 실제 시연 또는 재생/합성 구분을 유지한다. 이번에는 Google Slides를 변경하지 않았다.
