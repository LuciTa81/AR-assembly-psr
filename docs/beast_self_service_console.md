# 노트북 관제 실행 안내

현재 Windows 시연 환경의 사용자 안내입니다. 개발 당시 설계와 시험 기록은 [과거 기록](beast_self_service_console_history.md)에 보존합니다.

## 화면과 주소

기본 주소는 **http://127.0.0.1:8764/** 입니다.

| 메뉴 | 기능 |
| --- | --- |
| 실시간 관제 | 카메라 영상, 현재 작업·다음 행동, 작업 순서, 사용자 확인 |
| 작업 기록 | 단계 전환 중심의 기록, 전체 변화·보류 필터, JSON 내려받기 |
| 연결·진단 | 마커·도구 관측, 처리 속도, 수신 데이터 나이, 공간 안내 상태 |
| 설정 | 테마, 동작 효과, 포인터 강조, 영상 표시 |

이 주소는 같은 노트북에서만 접근하는 loopback 관제입니다. 휴대폰이나 다른 PC에서 접근하는 원격 관제는 아직 제공하지 않습니다.

직접 실행한 인식 서버의 `http://127.0.0.1:8765/supervisor.html`은 별도 경로입니다. 카메라가 꺼져 있을 때도 시작·종료를 관리하려면 8764 컨트롤러를 사용합니다. 단순 HTML 파일 열기로는 실행 관리를 할 수 없습니다.

## 기존 설치 환경에서 사용

1. Beast와 노트북을 연결합니다.
2. Full SBS, 0DoF, Extra Large, 4.5m, Windows 확장 모드를 확인합니다. 기존 관제의 화면 검사 기준은 3840×1080입니다.
3. 기존 **AI Assembly Guide** 바로가기로 관제를 엽니다.
4. **연결 확인**을 누릅니다. 파일·보정, 장치, 확장 화면, 다른 실행 여부를 점검하며 카메라 캡처를 열지 않습니다.
5. 착용 위치와 상자·마커 배치를 확인하고 체크한 뒤 **작업 시작**을 누릅니다.
6. **영상 표시**를 켜 카메라가 실제 작업대를 보고 있는지 확인합니다.
7. 상자·뚜껑을 직접 확인하고, A~D 안내를 따라 진행합니다. 마지막에는 전체 조립 상태를 직접 확인합니다.
8. **실행 종료**를 눌러 대기 상태로 돌아왔는지 확인합니다.

안경 문구와 색은 작업자의 다음 행동을 안내합니다. 카메라 화면은 눈별 AR 오버레이를 그대로 촬영한 화면이 아닙니다.

## 시작·종료와 영상

- 페이지 열기와 연결 확인만으로 카메라가 켜지지 않습니다.
- 작업 시작 시 인식 서버와 Unity를 시작합니다. 영상 표시 스위치는 브라우저 미리보기만 제어하며, 끈다고 인식용 카메라가 꺼지지는 않습니다.
- 영상 표시는 기본 꺼짐이며 새로고침하면 다시 꺼집니다. 기본 관제는 사진·영상 파일을 저장하지 않습니다.
- 새로고침·탭 닫기는 실행 종료가 아닙니다. 다시 열어 실행 종료를 눌러야 합니다.
- 완료 후에도 관제 실행은 종료 버튼을 누를 때까지 유지됩니다.
- 종료 후 다시 시작하면 새 세션으로 상자 배치부터 시작합니다.
- 실행 관리자는 자신이 시작한 프로세스를 정리합니다. 관련 없는 Python 프로세스를 일괄 종료하는 기능은 아닙니다.

## 작업 기록

기본 필터는 **단계 전환**입니다. **전체 변화** 또는 **보류·재확인**을 선택할 수 있습니다.

이 목록은 현재 페이지가 수신한 상태 변화의 제한된 이력입니다. 페이지를 닫고 다시 열었을 때 서버의 과거 기록 전체를 복원하는 영구 기록 뷰어는 아닙니다. 기록 내려받기는 브라우저가 수집한 이력을 JSON으로 내보냅니다.

서버의 숫자 로그와 관제 실행 로그는 로컬 폴더에 별도로 남습니다.

## 소스와 로컬 실행 파일 준비

공개 Git에는 소스와 일부 보정·설정이 있으며 모델·성공 Player·실행 로그·영상은 없습니다.

필요한 항목:

- Python 실행 환경과 [실시간 의존성](../server/realtime/requirements-realtime.txt).
- `models/yolo/driver_standard_model/best-3.pt`.
- 검증한 카메라·작업대·눈별 보정과 해당 파일을 참조하는 표시 프로필.
- `trial_directory`의 외부 런처, joint 후보, 검증 메타데이터와 성공 빌드.
- 한글 안내를 사용할 경우 `action_guidance_directory`의 `run-korean-trial.ps1`과 `player-v2`.
- `profile.json`의 각 경로 및 외부 스크립트 내부의 절대 경로 점검.

[예제 프로필](../configs/beast_console.example.json)은 구조 설명용입니다. `C:/ARAssembly/...` 파일이 자동 생성되거나 다운로드되는 것은 아닙니다. 실행 중인 PC의 프로필을 예제로 덮어쓰지 않습니다.

| 프로필 필드 | 의미 |
| --- | --- |
| `schema_version` | `beast_console_profile_v1` |
| `python` | 인식에 사용할 로컬 Python 실행 파일 |
| `trial_directory` | 기존 복구·윤곽·보정 실행 지원 폴더 |
| `action_guidance_directory` | 선택적 한글 안내 후보. 생략하면 기존 런처/빌드 경로 사용 |
| `presentation_config` | 선택적 표시 프로필. 생략하면 저장소의 `outputs/demo/presentation.json` 사용 |

실제 프로필을 준비한 후 저장소 루트에서 실행합니다.

```powershell
.\scripts\open_beast_console.ps1 -Profile C:\ARAssembly\console\profile.json
```

포트 충돌 시 `-Port 8766`처럼 다른 포트를 명시할 수 있습니다. 이미 같은 콘솔이 실행 중이면 기존 페이지를 엽니다. 다른 서비스를 임의로 종료하지 않습니다.

## 문제가 생기면

| 증상 | 확인할 것 |
| --- | --- |
| 시작 버튼 비활성 | 연결 확인 결과와 착용·설정 체크 |
| 검은 영상 영역 | 실행 상태, 영상 표시 스위치, 카메라 번호·권한·연결 |
| 실행 중단 메시지 | 프로필 옆 `runs/<run_id>/launcher.log`, 경로·Player·보정 해시 |
| 장치/화면 검사 실패 | Full SBS와 Windows 확장 모드, 실제 3840×1080 화면, 다른 실행 |
| 원·윤곽 끊김 | 마커 가림과 추적 유효성. 화면을 유지하려고 임의로 보정이나 유효성 검사를 바꾸지 않기 |
| 브라우저 연결 끊김 | 실제 작업을 멈추고 컨트롤러·실행 상태 확인 |

콘솔 자체 로그는 프로필 폴더의 `console.log`, `console-error.log`이며, 연결 검사는 `checks/`, 실행 관리는 `runs/`에 저장됩니다. 외부 런처가 남기는 숫자 로그의 위치는 해당 런처 설정을 따릅니다.

## 현재 유지하는 정책

상자·뚜껑·최종 검사는 수동 확인입니다. 기본 나사 단계는 접근·유지·이탈 판단을 사용합니다. 촬영용 초록 후 자동 전환, 새 3초 설정, 상자·뚜껑 자동 확인과 Android 실행은 이 안내의 기본 기능이 아닙니다.
