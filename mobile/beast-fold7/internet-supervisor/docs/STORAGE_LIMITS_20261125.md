# 녹화 보관 한도 확대

2026-11-25 KST 사용자 요청으로 운영 서버에 적용했다.

| 항목 | 변경 후 |
| --- | --- |
| 본인 계정 총 보관량 | 10,000,000,000 bytes (10GB) |
| 녹화 한 건 용량 | 300,000,000 bytes (300MB) |
| 녹화 최대 시간 | 기존 600초 유지 |
| 보관 기간 | 기존 완료 후 7일 유지 |
| 동시 녹화 | 기존 1개 유지 |
| 공개 가입 | 기존 MULTI_USER=false 유지 |

서로 다른 기기도 같은 계정이면 총 보관 한도를 공유한다. 녹화는 시간,
용량, 남은 계정 보관량 중 먼저 도달하는 제한에서 끝난다. 중단 후 복구된
분할 구간도 기존 작업 세션의 용량/시간 예산을 공유한다.
이는 S3 선할당이나 비용 상한 설정이 아니며 실제 저장/요청/다운로드에 따라
비용이 발생할 수 있다. FPS/비트레이트/AR 보정은 변경하지 않았다.

## 변경 및 검증

- `server/config.ts`의 계정 용량 검증 상한을 5GiB에서 정확히 10GB로 확대했다.
- 10GB/300MB/600초 설정, 상한 초과 거부, 계정 용량이 파일 한도보다 작은 경우 거부를 검사했다.
- 격리된 PGlite 테스트에서 300MB 예약 33개와 잔여 100MB 예약 후 추가 예약 거부를 확인했다.
  실제 대용량 파일이나 S3 업로드를 만들지 않았다.
- Node 테스트 125개 통과, TypeScript `--noEmit` 통과.
- 운영 DB와 환경 파일을 먼저 백업했고, 촬영/녹화 중이 아님을 확인한 뒤 AR 서비스만 재시작했다.
- 실제 프로세스 환경의 한도, 인증된 녹화 목록 API, 공개 HTTPS `/health`를 확인했다.
- 재시작 전후 recordings/recording_accounts 행이 동일함을 비교했다.
- 확인 당시 계정 사용량은 42,215,372 bytes, API 목록은 3개였다.
  이전 대화의 약 27MB 잔여량 추정 대신 실제 서버 계정 사용량을 기준으로 한다.
- `ActiveState=active`, `Result=success`, `NRestarts=0`. NOVA 상태는 변경하지 않았다.
- 앱과 웹에 100MB 한도가 고정 표시된 부분이 없어 앱/웹 재배포는 하지 않았다.
- 실제 300MB 한계까지 촬영하거나 10GB를 채우는 운영 시험은 하지 않았다.

운영 릴리스: `/opt/ar-assembly/releases/20261125-07-storage-10gb`.
백업: `/var/backups/ar-assembly/pre-storage-10gb-20261125T143016Z`.
이전 릴리스: `/opt/ar-assembly/releases/20261125-06-ten-minute`.
배포 스크립트는 검증 실패 시 이전 설정/릴리스로 되돌리며 기존 DB/영상은 삭제하지 않는다.
