# C3: 임시 모서리 지도 기반 부분 가림 후보

## 결론과 상태

C2의 중심점 외삽 대신, 현재 실제로 보이는 마커의 모서리 12~16개로 직접 자세를 계산한다.
5개 이상이 정상 검출되는 화면에서 임시 지도를 만들고, 최근 8장/4장 모델을 함께 사용한다.
좌우 가림의 비교 오차와 유지율은 개선됐지만, 초기 학습 전 가림에서는 C2보다 늦게 표시된다.
모든 상황의 상위 호환이나 실기 성공본으로 간주하지 않는다.

- APK 빌드 및 로컬 테스트 완료. 아래 실기 검증 기록에 설치/네이티브 실행 결과를 추가했다. 착용 시험은 미실시.
- v1, C1, C2 APK 보존. 카메라/작업대/눈별 보정 파일 변경 없음.
- 카메라 시작, 새 사진/영상 저장, 서버/웹 배포 없음.
- 앱 패키지: `com.lucita.beastgate.trackingcandidate` (v1과 별도).
- 버전: `1.4.2-partial-markers-c3`.
- APK: `releases/AR-Assembly-Tracking-C3-20261125.apk`.
- SHA256: `C2BB8C6439B0A1695C418411308EB7B0CAA0A52E3E9AD4140269800A89A17926`.

## 조사에서 달라진 판단

이전의 모서리 지도 실패는 주로 SUBPIX 관측으로 평가했다. APRILTAG 모서리 정밀화 관측으로
다시 비교하니 직접 모서리 풀이가 유망했다. 다만 지도에 등록 중심을 강제로 다시 맞춘
`centered8` 변형은 3마커 양쪽에서 비교 오차가 커져 폐기했다. 69/70mm를 임의로 확정하거나
205/205를 변경하지 않았다. 최신 논문을 적용했다고 표현하지 않는다.

[OpenCV ArUco FAQ](https://docs.opencv.org/4.13.0/d1/dcb/tutorial_aruco_faq.html)는
보드의 여러 모서리를 함께 이용하는 자세 추정과 부분 가림 대응을 설명한다. 여기서는
측정 완료된 보드를 새로 등록한 것이 아니라 기존 좌표계 안의 **실행 중 임시 추정 지도**를 쓴다.
따라서 공식 보드의 일반적 장점이 우리 앱의 절대 정확도를 입증하는 것은 아니다.

[ReTracker, ICCV 2025](https://openaccess.thecvf.com/content/ICCV2025/html/Tan_ReTracker_Exploring_Image_Matching_for_Robust_Online_Any_Point_Tracking_ICCV_2025_paper.html)도
추적 소실 후 영상 대응을 다시 찾는 연구로 조사했다. Fold7 실시간 실행과 우리 작업대의
눈별 투영 정확도를 검증하지 않았으므로 모델/코드를 이번 APK에 추가하지 않았다.

## 구현과 보호 조건

- 전체 5마커 정상 프레임은 기존 정밀 중심점 자세를 그대로 반환한다.
- 최소 500ms 간격으로 정상 프레임을 모은다. 최소 4장 필요: 이상적 조건에서도 1.5초 이상.
- 각 정상 자세에서 관측 모서리를 Z=0 작업대에 역투영. 실행 메모리에만 보관한다.
- 최근 8장 지도와 최근 4장 지도 각각에 전체/짝수/홀수 표본의 좌표별 중앙값 모델을 만든다.
- 서로 다른 표본 모델의 A~D 계산이 3px 및 3mm 이내로 일치해야 한다.
- 마커 그룹 하나를 제외한 재계산도 같은 기준으로 검사한다. 두 마커 계산은 내부 민감도 검사이며 표시에는 사용하지 않는다.
- 모서리 재투영 RMS 1.5px, 최대 3px 이하. 기존 중심점 제한 3.2/5px를 완화하지 않았다.
- 기존 물리 자세, 평면 모호성, 정제 검사 유지.
- 3마커 중심이 일렬에 가까우면 SVD 비율 0.05 기준으로 거부한다. 특정 ID만 임의 차단하는 방식이 아니다.
- 최소 3마커, 마지막 지도 갱신 후 최대 30초. 부분 관측은 만료 시간을 연장하지 않는다.
- 손/상자가 움직였다고 지도를 자동 재보정하지 않는다. 마커/작업대가 고정되어 있다는 기존 전제가 필요하다.
- 작업 재시작/시간 역행에서 초기화. 이전 화면 좌표를 고정해 유지하지 않는다.
- 기존 검출기 fallback 유지. C2를 불확실 구간의 무조건 fallback으로 추가하지 않았다.

## 최대 30초 좌우 가림 재현

동일한 과거 기준 시점, 동일한 가림 관측으로 비교했다. 가림 이후 숨긴 모서리는
비교 기준 계산에만 사용하며 후보 학습에는 쓰지 않았다.

| 자료 / 숨긴 마커 | 사례 | C2 표시 판정 | 최종 C3 표시 판정 | C3 비교 기준 내 |
| --- | ---: | ---: | ---: | ---: |
| 성공 영상 / 오른쪽 2,5 | 3263 | 2075 (63.6%) | 2506 (76.8%) | 2506 |
| 성공 영상 / 왼쪽 0,4 | 3263 | 1758 (53.9%) | 2462 (75.5%) | 2462 |
| 별도 촬영 / 오른쪽 2,5 | 66 | 31 (47.0%) | 49 (74.2%) | 49 |
| 별도 촬영 / 왼쪽 0,4 | 66 | 12 (18.2%) | 51 (77.3%) | 51 |

이 사례들의 최종 C3 최대 카메라 차이 2.65px, 최대 좌표 차이 2.67mm.
최대 눈별 투영 차이 5.81px. 비교 기준은 기존과 같은 5카메라px AND 5mm이다.
반환된 결과가 비교 기준 안이라는 뜻이지, 실제 물체와 절대 오차가 그 값이라는 뜻은 아니다.
겹치는 시간 창에서 나온 상관된 사례이며 독립된 촬영 3263회를 뜻하지 않는다.

8장 단독 지도에서 다중 지도 조합으로 추가된 좌우 사례는 성공 영상 116/95건,
별도 촬영 4/2건이며 모두 비교 기준 이내였다.

## 다른 조합과 실제 관측 흐름

모든 3/4마커 조합을 다음 관측에서 검사했다. 이 시험은 위의 지속 가림 시험과 구분한다.
현재 프레임으로 지도 학습 전에 검증하므로 현재/미래 관측 누출은 없다.

| 자료 | 3마커 판정 | 4마커 판정 | 반환된 결과 중 비교 기준 초과 |
| --- | ---: | ---: | ---: |
| 성공 영상 | 941/1300 | 610/650 | 0 |
| 별도 촬영 | 84/140 | 50/70 | 0 |

3마커에는 일렬 조합 거부(130/14건)와 초기 학습 미완료가 포함된다.
초기 단일 지도 실험에서 일렬 0,1,2 조합의 1건이 5px를 초과했고, 이를 숨기지 않고
기하학적 차단 회귀 테스트를 추가했다. 원 결과는 `c3-all-subsets.json`에 보존했다.

실제 관측 순서에서 동일한 legacy fallback을 포함한 반환 수:

| 자료 | v1 | C2 | C3 | 전체 프레임 |
| --- | ---: | ---: | ---: | ---: |
| 성공 영상 | 159 | 211 | 208 | 239 |
| 별도 촬영 | 19 | 43 | 34 | 46 |

**C3는 초기 학습 때문에 실제 전체 관측 반환 수에서 C2보다 적다.** 특히 별도 촬영은
충분한 5마커 초기 화면이 부족했다. 이 구간의 실제 나사 정답 위치는 없으므로 반환 수를
정확도나 완성도로 바꾸어 표현하지 않는다. 초기 학습에 C2 fallback을 쓰는 실험은
34에서 41건으로 늘었지만, 이번 APK에는 적용하지 않았다.

## 검증 및 남은 항목

- Python 41개, JVM 41개 통과. 후보 APK/시험 APK 빌드 성공.
- Lint 오류 0개, 경고 22개.
- Android 카메라 없는 수치 fixture: 단일 지도 27개(16 성공 예상), 다중 지도 26개(14 성공 예상).
- 네이티브 fixture의 Android 실행은 아래 기록에서 통과. 실제 카메라 처리 속도/발열/깜빡임은 미검증.
- Python은 전체 A~D 좌표를 검사하고, Android는 A~D가 카메라 화면 안에 있어야 교차 검사를 통과한다.
  화면 밖 구도에서 Android가 더 보수적일 수 있다.
- 기존 특징점 추적은 계속 APK 미포함. 이전 오차 사례가 해소됐다고 주장하지 않는다.

다음은 기기 연결 후 수치 시험, 5마커를 4초 정도 본 다음 좌우 가림/복귀 착용 비교다.
5개 상태에서도 v1 위치와 비교해야 한다. 새 녹화나 작업대 이동, 추가 조임은 필요 없다.
초기 3마커만으로 시작하거나 30초 넘게 계속 3마커만 보이는 조건은 별도 과제로 남는다.
