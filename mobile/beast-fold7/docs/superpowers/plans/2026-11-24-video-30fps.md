# 30fps 목표 영상 관제 계획

## 목표와 결정

사용자는 5fps를 거절하고 30~60fps 수준의 자연스러운 영상 및 서버/웹 반영을 요청했다. 기본 목표는 1280x720, H.264 baseline, 30fps, 약 2Mbps다. 기존 카메라 요청은 이미 720p30이지만 실제 로그에는 약 20fps 구간도 있어 30fps 고정이나 60fps 달성을 주장하지 않는다. 실카메라 검증은 아직 보류 상태다.

기존 JPEG 후보는 별도 보관한다. Android MediaCodec 하드웨어 인코더와 Chrome/Edge WebCodecs 디코더를 사용하고 별도 인증 WSS 경로로 전달한다. 새로운 TURN 서비스/비용/방화벽 변경은 하지 않는다. 이 선택은 WebRTC가 아니며 TCP 혼잡시 지연 가능성이 있다. 전송/디코드 큐를 제한하고 프레임 누락 후 키프레임에서 재개한다. 지원되지 않는 브라우저는 명확히 안내한다.

## 제약

- AR 분석 주기, 기존 A-D 보정, 카메라 해상도, 단계 판정 불변.
- 카메라 입력 후 영상 분기와 5fps 분석 분기를 분리한다.
- 영상 공유는 별도 동의, 기본 꺼짐. 음성/영상 저장 없음.
- 서버 영상 영구 저장/프레임 재생 버퍼 없음. 인증, 소유자 격리, 동의 상태, 종료, 권한 해제를 검사한다.
- 영상 패킷은 버전/순서/PTS/해상도/키프레임 표식을 포함하고 크기와 전송률을 제한한다.
- 실제 fps는 입력/인코더/네트워크에 따라 달라진다. 합성 30fps 검증과 Fold7 실기 결과를 구분한다.

- [x] Android H.264 인코더와 카메라 분기 분리, 단위 테스트/APK 빌드.

- [x] 전체 테스트/타입/빌드, APK 보정 자산 비교.
- [x] EC2 기존 릴리스/DB 보존 후 중계 업데이트, Vercel 웹 업데이트, 운영 합성 시험.

## 검증 결과

- 서버 82개, Android 37개 테스트 통과. Android lint 오류 0, 경고 21. Next 프로덕션 빌드/타입 검사 통과.
- 합성 브라우저 영상은 Windows 테스트에서 내부 표시율 24fps를 관측. 30fps 타임스탬프와 전송 목표를 실제 30fps 달성으로 표현하지 않는다.
- 기본 Windows 디코더는 초기 4개 프레임을 출력하지 않았고, 지원되는 소프트웨어 디코더는 즉시 출력했다. 지원 검사 후 소프트웨어 우선, 미지원이면 기본 디코더를 사용한다.
- 운영 중계 `/opt/ar-assembly/releases/20261124-03`, 이전 `02` 유지. DB 백업 후 TLS/WSS 합성 30패킷 순서/동의 종료/해제 시험 통과. NOVA inactive 유지.
- Vercel 운영 배포 `dpl_Fm1dMTVkZH4wtdSju55aqr8KrJZt`, 기존 주소 유지. 로그인 200, 비로그인 관제 API 401, GitHub provider 정상.
- 실제 Fold7 MediaCodec 출력, 발열, AR 병행 성능, 모바일데이터 영상 지연은 아직 미검증.

공식 근거: Android MediaCodec getInputImage / COLOR_FormatYUV420Flexible; W3C WebCodecs AVC Annex B key chunk requires IDR plus parameter sets. 입력 FPS 근거는 프로젝트 저장 로그이며 현재 실측이 아니다.
