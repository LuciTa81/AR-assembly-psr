# Multi-Glasses Port: 조건부 개발 로드맵

작성: 2026-11-25. **조사 기반 제안이며 구현·촬영·배포 승인으로 간주하지 않는다.**

**Goal:** Fold7의 인식과 작업 흐름을 유지하면서 Meta Ray-Ban Display 및 디스플레이형 Rokid Glasses에서 현재 작업 HUD와 본인 웹 관제를 제공한다.

**Architecture:** 기존 앱의 카메라 입력과 안내 출력을 기기별로 연결한다. 공통 인식·상태·인증을 재사용하고 Beast의 UVC/양안 출력은 보존한다. 첫 후보는 각각 분리된 설치 ID/소스셋으로 검증한다.

**Tech Stack:** 기존 Java17·Android36·OpenCV·ONNX Runtime·MediaCodec·OkHttp, Meta DAT 1.1.0용 최소 Kotlin 브리지, Rokid의 승인된 해당 기기 SDK. 기존 Node/Next.js/Postgres/S3 후보 코드는 필요한 호환 검증에만 사용한다.

**Spec:** [기기/API/코드 조사](C:/Users/fresh/Documents/Codex/Beast-Fold7-Gate/docs/research/2026-11-25-meta-rokid-feasibility.md).

**Constraints:** 기존 A~D 보정 및 205/205 기준본 불변. 폰·클라우드 영상 및 녹화는 각각 명시적으로 동의한 경우만. 음성 수집 없음. 비공식 펌웨어·권한 우회·공급사 라이선스 우회 없음. 비용·배포는 별도 승인.

**Review Focus:** 기기 미지원 기능을 지원한다고 표시하지 않는가, 영상 기하가 보존되는가, 잘못된 프레임/화면 승인으로 단계가 넘어가지 않는가, 다른 계정의 영상에 접근할 수 없는가, Beast 기준본이 그대로 동작하는가.

## 범위와 일정

모든 시간은 **엔지니어링 추정**이며 공급사 승인·배송·계정 심사·사용자 실험 대기는 제외한다. SDK를 정상 사용할 수 있고 기존 모델을 재학습하지 않는 HUD 중심 범위다.

| 순서 | 산출물 | 예상 집중 작업 | 다음 단계 조건 |
| --- | --- | --- | --- |
| 0 | 기준본 보관·공급사 접근 조건표 | 4~8시간 | 정확한 모델·SDK·허용 경로 확인 |
| 1 | Meta 카메라 + HUD 독립 시제품 | 8~16시간 | 동시에 동작하고 종료·권한 거부 처리 |
| 2 | Rokid 카메라 + HUD 독립 시제품 | 12~24시간 | 승인 SDK에서 연속 영상과 표시 확인 |
| 3 | 기존 앱에 최소 공통 경계 연결 | 8~16시간 | 가짜 입력 회귀 테스트와 Beast 빌드 유지 |
| 4 | 두 기기 인식·카메라 보정·웹 통합 | 16~32시간 | 전체 흐름과 영상 호환 확인 |
| 5 | 장시간·권한·복구·녹화 검증 | 12~24시간 | 실기기 인수 기준 통과 |
| 합계 | 두 기기의 HUD 시연 후보 | **60~120시간** | 승인 대기 및 정밀 현실 정합은 별도 |

한 기기의 연결 시제품은 수십시간 이내를 목표로 잡을 수 있지만, 두 기기의 안정된 완성본을 같은 시간으로 약속하지 않는다. 공급사 API 제약·발열·새 모델 학습이 필요하면 단계 1/2 종료 시 재산정한다. 1/2는 접근 가능한 기기부터 수행한다.

## 단계 1. Meta 독립 입출력 검증

- [ ] 한글 행동 문구·대상 그림·종료만 표시한다. 처음부터 정밀 나사 오버레이나 3D 애니메이션을 붙이지 않는다.

**통과:** 사용자 승인한 카메라 프레임과 한글 HUD가 동시에 작동. 중지 시 촬영·표시·전송이 종료. 자료 저장 없이 수치만으로 가능한 검증부터 진행.

## 단계 2. Rokid 독립 입출력 검증

후보 경로 제안: `experiments/rokid-access/`. 정확한 API 식별자는 승인된 SDK를 받은 후 기록한다.

**통과:** 공급사가 허용한 경로로 연속 영상·화면·네트워크를 동시에 사용. 안 되면 전체 이식 일정 재산정.

## 별도 연구: 실제 나사 위 정합

HUD 완료와 별개로 진행 여부를 결정한다. 우선 공급사에 다음 접근이 가능한지 확인한다.

- 임의 화면 좌표 렌더링과 실제 표시 영역/광학 변환.
- 카메라 영상의 K·왜곡·동적 잘림 및 촬영 시각.
- 카메라-눈 관계, 표시 시각, 동작 시 지연 보상에 필요한 정보.
- Rokid의 경우 독립 좌우 이미지 제공 여부.

지원되는 기기만 새 보정 데이터로 정면·거리·측면·복귀를 검증한다. Meta는 단안 정합 실험을 하더라도 Beast와 같은 양안 입체 출력이라고 부르지 않는다. API가 없으면 HUD가 제품의 정식 범위이며, 비공식 접근으로 기능을 강행하지 않는다. 이 단계는 **60~120시간 산정에 포함되지 않는다.**

## 사용자에게 필요한 참여

1. 정확한 안경 모델·보유/구매 계획 확인.
2. 공급사 계정 로그인, 약관·개발 모드·SDK 승인 및 필요한 경우 심사.
3. 기기 설치·카메라·영상 전송·녹화 각각의 승인.
4. 렌즈 속 한글 가독성과 실제 위치 확인. 화면 캡처만으로 대신할 수 없다.
5. 비용 또는 공개 배포 범위가 바뀔 때 승인.

그 외 코드 작성·모의 입력 테스트·빌드·문서·기존 서버 호환 검증은 준비된 권한과 환경 범위에서 자동화한다. 지금은 이 계획과 조사 문서만 작성했으며, 위 체크 항목을 수행한 것으로 표시하지 않는다.
