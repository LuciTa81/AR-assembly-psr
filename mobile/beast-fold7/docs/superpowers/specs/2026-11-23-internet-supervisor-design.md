# Fold7 인터넷 관제 설계

작성: 2026-11-23. 상태: 사용자의 '쭉 진행해줘' 승인 후 로컬 구현 중. 실제 배포/인터넷 관제 완료를 뜻하지 않는다.

## 이번 점검 결과

- v1 manifest 90개, standalone-accepted manifest 61개: SHA256 불일치 0개.
- 기존 `supervisor-browser-test.cjs` 재실행 통과: 단계/phase, 기록 필터, stale/복귀, 새 세션, 인증 만료, 4개 viewport, 브라우저 오류 없음.
- 별도 읽기 전용 builder 검토: 빌드 계획을 막는 중요한 미결정 사항 없음.
- 현재 Android 작업 폴더는 Git 저장소가 아니다. 파일 백업과 Git 업로드는 구분하며, 구현 전 별도 로컬 변경 추적/보관을 마련한다. 원격 push나 기존 공개 저장소 반영은 별도 확인한다.
- 앱/AR 코드와 기존 보관본 변경 없음. 폰 설치/카메라 실행, EC2/Vercel 배포 없음.
- 설계 승인 요청을 사용자에게 전달했다. 승인 후 구체적인 구현 순서와 테스트 계획을 작성한다.

## 목표와 승인된 범위

- Fold7 + Beast의 기존 조립 안내를 유지하고, 다른 네트워크의 브라우저에서 상태를 확인한다.
- 사용자는 본인 전용 관제를 선택했다. 공개 회원가입과 여러 관제자 초대는 제외한다.
- 기존 검은 관제 디자인, 한국어 안내, 단계 전환 위주 기록을 유지한다.
- 상태 관제 -> 인터넷 실기 검증 -> 영상 -> 선택적 저장 순서로 나눈다.
- 인터넷/서버 장애가 AR 판단, 렌더링, 사용자의 종료 동작을 막아서는 안 된다.
- 성공본, A-D 눈별 보정, 205/205 좌표, 추적 임계값, 모든 단계 타이밍은 변경하지 않는다.

## 현재 코드에서 확인한 사실

- `SupervisorState.java`가 현재 상태 JSON(schema 1)을 만든다. stage -1, 0..6, phase, action, tracking, overlay, frame 등이 이미 있다.
- `MainActivity.java`의 `supervisorSnapshot()`을 통해 관제가 상태를 읽는다. AR 제어를 할 필요가 없다.
- `SupervisorLink.java`는 선택적으로 같은 Wi-Fi의 HTTP 서버를 열고 250ms마다 상태를 갱신한다.
- `assets/supervisor/observer.js`는 응답 후 500ms마다 조회한다. 기록은 브라우저 메모리의 최근 240개뿐이다.
- 기존 LAN 관제는 새 인터넷 관제가 검증될 때까지 보존한다. LAN의 공유 토큰을 인터넷 인증에 재사용하지 않는다.
- 앱은 백그라운드로 가면 카메라를 종료한다. 이번에 백그라운드 카메라/서비스 동작을 추가하지 않는다.
- 최종 검사 단계 진입은 체결 품질 검증이나 사용자 확인 클릭과 동일하지 않다. 현재 앱에서 관측 가능한 사실만 기록한다.

## 참고 코드와 선택

1. 기존 LAN 페이지 + EC2 중계: 변경은 작지만 계정/기기/기록 화면 확장 시 별도 구조 정리가 필요하다.
2. Next.js 웹 + 독립 상태 중계 서버: 화면과 앱을 분리하고 인증/기록을 확장하기 쉽다. 사용자가 앞서 승인한 방향이다.
3. SafeOps 플랫폼 전체 도입: 다중 카메라, 큐, Redis 등 현재 요구보다 큰 범위이므로 채택하지 않는다.

설계자 제안: 2번을 다음 기술로 구체화한다. 서버 프레임워크와 DB 선택은 아직 사용자 지정 사항이 아니다.

- 웹: Next.js + TypeScript, Vercel. 기존 색/레이아웃/폰트를 사용하고 UI를 재디자인하지 않는다.
- 백엔드: Node.js + TypeScript, HTTP API + 표준 WebSocket(`ws`), EC2의 독립 서비스.
- DB: PostgreSQL, 사용자/기기/세션/단계 이벤트. Redis와 Celery는 초기 도입하지 않는다.
- 앱: Java 유지. 검증된 Android WebSocket 라이브러리를 사용하고 별도 전송 계층만 추가한다.
- 로그인: 검증된 인증 라이브러리의 GitHub OAuth. 운영자가 지정한 GitHub 숫자 사용자 ID 한 개만 허용한다.
- 기존 회사 저장소는 참고용으로만 읽는다. 비밀값/운영 설정/회사 데이터는 복사하지 않는다.

SafeOps에서 확인한 것은 Next.js + Django REST 및 MySQL 의존성, Redis/Celery이며, 확인한 liveSnapshot 경로는 기본 5초 폴링이다. IVS Stage 영상 코드는 상태 전달과 별개다. sentientsys-web에서는 API 계층/관리자 인증과 출처 제한 패턴을 참고했다. 이들 저장소를 소켓 기반이라고 가정하지 않는다.

## 연결 구조

```text
Beast -- USB-C --> Fold7 (인식 / 판단 / AR, 인터넷 없이 실행)
                       |
                       +-- HTTPS 기기 등록 + WSS 상태 업로드 --> EC2 relay
                                                               |   |
                                  브라우저 <-- WSS 읽기 구독 ----+   +--> PostgreSQL
                                      |
                            Next.js 웹 / Vercel
                            GitHub 로그인 + 서버측 API 중계
```

브라우저 로그인 쿠키는 Vercel 웹 출처에만 둔다. 브라우저가 EC2의 제3자 쿠키에 의존하지 않는다. 로그인한 Next.js 서버가 EC2에 단기 구독 티켓을 요청한다. 티켓은 일회용, 30초 만료, 대상 기기/사용자/읽기 권한에 묶고 브라우저 메모리에만 둔다. WSS 연결 후 첫 인증 메시지로 전달하며 URL, access log, localStorage에 넣지 않는다. 인증 전에는 상태를 보내지 않고 5초 내 인증 실패 시 연결을 닫는다. 미인증 연결에도 수/크기/시간 제한을 둔다.

Next.js -> EC2 서버 간 비밀값은 서버 환경변수에만 둔다. NEXT_PUBLIC 변수나 브라우저 번들에 넣지 않는다. 모든 REST 요청과 WSS 구독에서 사용자와 기기 소유권을 검사한다. 구독 티켓은 접속 인증용이고 연결 권한은 최대 15분 후 재확인한다. 로그아웃/기기 해제는 활성 연결도 종료한다.

## 폰 연결과 권한

1. 폰에서 사용자가 인터넷 관제를 켜고 연결 코드를 요청한다. 상태/진단 숫자 전송 범위를 설명한다.
2. 폰에는 CSPRNG 8자리 연결 코드와 5분 만료를 표시한다. 폰은 별도의 고엔트로피 polling secret으로 승인 상태를 확인한다.
3. 본인으로 로그인한 웹에서 코드를 입력하고 기기명을 확인한 뒤 승인한다.
4. 폰은 발급된 기기 자격증명으로 자기 기기의 상태만 보낸다. Android Keystore로 보호해 저장하며 앱 백업에서 제외한다.
5. 웹에서 기기를 해제하면 기존 기기 토큰과 활성 업로드/구독을 무효화한다. 재연결에는 새 승인이 필요하다.

코드 추측/승인/polling/API에 속도 및 시도 횟수 제한을 둔다. 토큰은 서버에 해시로만 저장하고 만료/폐기할 수 있어야 한다. 토큰 원문, OAuth 비밀, SSH 키는 로그/저장소에 남기지 않는다. HTTP/ws 평문은 명시적인 localhost 테스트에서만 허용한다.

## 상태 프로토콜

- 전송 wrapper: `protocol`, `stream_id`, `seq`, `sent_at_ms`, `state`(기존 schema 1 snapshot).
- 기기 ID/소유자는 인증된 연결에서 확정한다. JSON이 주장하는 소유자를 신뢰하지 않는다.
- 작업 session은 기존 앱 값을 유지한다. stream_id는 전송 시작 시 생성하며 재연결 동안 유지한다. seq는 단조 증가한다.
- 한 기기에는 활성 publisher 하나만 허용한다. 새 인증 연결이 기존 연결을 교체하면 generation으로 이전 연결의 늦은 메시지를 거절한다.
- 메시지 크기 16KiB 이하, 전송 상한 초당 10회. 단계/phase 변경은 우선 전송하고 진단 수치는 최대 초당 4회, 유휴 상태 heartbeat는 1초 간격으로 한다.
- 앱의 네트워크 I/O는 AR/main thread에서 실행하지 않는다. immutable snapshot과 크기 제한 전송 큐를 사용한다.
- 혼잡 시 진단 snapshot은 최신 값으로 덮어쓴다. 무제한 큐나 끊긴 동안의 프레임 재생을 금지한다.
- 구독자는 상태와 함께 서버 수신 시각을 받는다. 3초 이상 새 상태가 없으면 stale로 표시하고 현재 행동/색상 강조를 지운다. 마지막 수신 상태는 과거 값으로만 표시한다.
- 재연결은 지수 백오프 + jitter(1..30초). 현재 최신 상태부터 복구한다. 폐기/만료 토큰은 자동 무한 재시도하지 않고 재연결 승인을 요구한다.
- wall-clock 차이만으로 전송 지연을 계산하지 않는다. 상대 monotonic 시간, seq, 서버 처리 시간, ping RTT로 분석하고 단방향 지연은 동기화 오차를 함께 기록한다.
- WebSocket은 웹 관제 전달 대기를 줄인다. 마커 추적 정확도와 의도적 단계 대기 시간을 바꾸는 기능이 아니다.

## 기록과 DB 실패

- 테이블: owner, device, pairing_request, device_credential, assembly_session, stage_event. 로그인 세션/구독 티켓 저장은 인증 계층에 맞춘다.
- 최초 수신, 단계/phase 변경, 사용자 종료와 관제 연결 단절을 구분한다. 앱이 제공하지 않는 종료 이유/사용자 확인을 추정해서 만들지 않는다.
- snapshot 전체를 매 프레임 DB에 저장하지 않는다. 중계의 최신 상태는 메모리, 의미 있는 변경만 DB에 기록한다.
- `(device_id, stream_id, seq, event_kind)` 등의 유일키로 재전송 중복을 막는다.
- 1차 버전은 인터넷 단절 중의 전체 작업 이력을 보장하지 않는다. 복귀 시 마지막 기록과 현재 상태 사이를 `수신 공백`으로 표시한다. 현재 단계만 보고 누락된 A/B/C 완료 이벤트를 생성하지 않는다.
- DB 기록 오류는 서버에서 제한적으로 처리하고, 웹에는 `기록 저장 지연/중단`을 표시한다. 이미 인증된 상태 중계와 폰 AR 실행은 계속할 수 있지만, 새 인증/기기 등록은 DB 복구 전 실패 처리한다.
- 초기 기록 보존 30일(설계자 제안), 영상 보존과는 별개. 실제 자동 삭제 작업은 운영 승인 후 켠다.

## 화면과 기능 경계

- 웹: 실시간 관제 / 작업 기록 / 기기·설정. 본인 로그인, 기기 연결/해제, 읽기 전용 관제.
- 기존 한국어 action/색상과 데이터 의미를 그대로 반영한다. 추적 상세는 접어둔다.
- 기본 기록은 단계 전환, 전체 보기에서 phase/연결 변화. 새로고침 후 서버의 저장 기록을 조회한다.
- 현재 단계 정보가 없을 때 임의의 기본 A 또는 완료 화면을 보여주지 않는다.
- 영상 미구현 상태에는 영상/녹화 토글을 동작하는 것처럼 제공하지 않는다. 이후 영상 공유 동의를 별도로 받는다.
- 원격 시작/종료/단계 건너뛰기/임계값 변경은 1차 범위가 아니다.
- 기존 앱의 onStop 카메라 종료 정책과 오프라인 단독 실행을 유지한다.

## 배포와 보관

- 로컬 프로젝트 `internet-supervisor/` 아래 web/server/shared로 분리. 앱 변경은 새로운 remote transport와 연결 UI 중심으로 제한한다.
- v1와 standalone 성공본은 덮어쓰지 않는다. 기존 파일 hash 목록을 검증하고 새 LAN 상태까지 별도 체크포인트로 보관한다.
- EC2 `54.116.139.37`에서 NOVA 중지 상태/CPU/RAM/disk/포트/방화벽을 읽기 확인한 뒤에만 배포한다. 기존 `/opt/nova`는 수정하지 않는다.
- API/DB는 독립 서비스/데이터 디렉터리/네트워크로 분리한다. DB는 외부에 공개하지 않는다. HTTP 앱 포트는 reverse proxy에서만 접근한다.
- TLS 종단은 EC2 HTTPS/WSS. Vercel HTTPS만으로 EC2 API가 암호화되는 것은 아니다.
- EC2 IP 안정성 및 AWS 보안 그룹 접근 권한을 확인한다. 사용자 도메인이 없으면 IP 인증서 또는 별도 DNS 중 실제 유지 가능한 방식을 선택한다. 인증서 갱신/외부 연결 검증 전 공개 완료로 보고하지 않는다.
- 새 유료 서비스, 도메인 구매, AWS 자원 증설, 기존 데이터 삭제, 저장소 공개 전환은 별도 확인한다.
- 기존 SSH key를 복사해 프로젝트에 넣지 않는다. 배포 비밀값은 환경변수/보호된 파일에만 둔다.
- Vercel 프로젝트/GitHub OAuth 앱/배포 저장소의 실제 계정과 승인은 배포 단계에서 확인한다. 현재 원격 배포는 미완료다.

| 7 | 선택적 녹화 | 별도 저장 동의/보존/용량/비용 결정, 시작·종료·다운로드·실패 확인 |

실기에서 카메라를 켜거나 APK를 교체하기 전 준비를 묻는다. 서버 로컬/합성 테스트 통과를 실제 Fold7 인터넷 검증으로 보고하지 않는다.

## 남은 결정과 제안

- 사용자 확정: 본인 전용, 기존 검은 화면 유지, 인터넷 관제, 성공본/보정 보존.
- 설계 승인 요청: GitHub 한 계정 로그인, Next.js + Node WebSocket + PostgreSQL, 상태부터 진행.
- 배포 전 확인: GitHub 숫자 계정 ID, Vercel/OAuth 승인, 실제 배포 저장소, EC2 고정 IP/TLS/보안 그룹 접근.
- 영상/녹화는 이 설계로 구현 승인된 것으로 보지 않고 후속 단계에서 확인한다.
