# 단독 실행 정리 후보

- 사용자 요청대로 205·205mm 배치와 기존 A~D 보정을 유지한 4초 파란 안내 버전을 `baseline/v1-frozen-20261121/`에 동결했다.
- APK, 검사 APK, 소스·자산·보정·빌드 설정, 검사 결과 등 90개 파일을 복사하고 각각 SHA256으로 검증했다. 단독 실행 수정 후에도 전체 동결 파일의 해시가 동일함을 재확인했다.
- [보관 내역과 복원 조건](V1_CHECKPOINT.md)

## 변경 범위

- `1.1-candidate` / versionCode 6, 앱 이름 **AR Assembly**.
- Android 런처에서 실행하면 별도 개발 옵션 없이 v1 전체 안내가 기본이다. 명시적인 기존 진단 모드 옵션은 원래 동작을 유지한다.
- 시작 버튼은 모델·보정 준비, Beast Full SBS 외부 화면, USB 카메라 장치 존재를 확인한 뒤 활성화한다. 카메라 장치 열기와 프레임 수신 성공은 실제 시작 후 확인한다.
- 종료는 카메라와 안내를 끄고 앱에 남는다. 다시 시작하면 상자 배치부터 새 세션이다. 실행 중 시작 버튼은 비활성화한다.
- 연결 확인 버튼은 현재 출력과 USB 장치 상태를 다시 읽는다. 잘못된 SBS 해상도에서는 시작하지 않는다.
- 앱 비활성화나 연결 끊김으로 중단한 작업을 복귀 시 자동으로 재개하지 않는다. 늦게 도착한 권한 승인만으로 카메라를 켜지 않는다.
- 일반 화면에서 숫자 진단은 기본 접힘. 실제 카메라 미리보기는 유지한다. 외부 화면 없이도 ‘시작 준비 완료’로 오해하지 않도록 모델 로딩 완료는 ‘인식 준비 완료’로 구분했다.
- 시작 후 15초간 프레임이 전혀 없으면 USB/권한 확인 메시지와 함께 종료한다. 기존 최대 5분 제한과 최종 검사 10초는 유지했다.

## 검증

- 수정 전 신규 검사에서 기본 전체 안내 선택과 종료 후 앱 유지가 실제로 실패하는 것을 확인했다 (`standalone-red-tests.txt`, 4개 중 2개 실패).
- 변경 후 기존 42개와 신규 7개를 합친 49개 기기 검사가 통과했다. 기본 옵션, 진단 옵션 유지, 종료 상태 초기화, 권한 거절, 앱 복귀/늦은 권한 결과에서 자동 실행 방지, 화면 크기별 버튼과 미리보기 영역을 검사했다 (`standalone-tests-device.txt`).
- 360×800, 690×830, 915×412 dp에서 앱 View를 기기에서 렌더링했다. 좁은 세로 및 가로 결과를 확인했고 버튼 글자 잘림·중첩은 없었다. 화면 자료는 `standalone-ui-qa/`이며 실제 카메라 사진이 아닌 앱 UI 렌더다.
- 런처와 동일한 MAIN/LAUNCHER 인텐트에 개발 옵션 없이 실행하여 `LAUNCH_MODE standalone_v1`, BOX_OUTLINE_READY, SCREW_CONTEXT_READY, TRACKER_READY, YOLO_READY를 확인했다. 카메라는 자동 시작하지 않았다.
- 동결본 대비 `app/src/main` 변경은 MainActivity와 AndroidManifest뿐이다. 보정·추적·단계 판정·색·3D 부품·윤곽 자산은 그대로다.
- 실제 USB 카메라 시작 → 종료 → 재시작, 물리적 재연결 및 Full SBS 전환 시험은 사용자와 확인할 항목으로 남아 있다. 상태 전환 자동 검사는 실제 장치 재연결 시험을 대체하지 않는다.
- 최종 문구 수정 후에도 전체 49개 기기 검사와 빌드·린트가 통과했다. 최종 UI 렌더는 `standalone-ui-qa-final/`에 별도 수집했다.
- 사용자가 설치까지만 진행하고 착용 시험은 나중에 하겠다고 요청했다. 설치된 `1.1-candidate`를 확인한 뒤 앱을 강제 종료했다. 실제 카메라 시험은 수행하지 않았다.
