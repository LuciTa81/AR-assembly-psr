# AI Assembly Guide

AR 안경으로 조립 위치와 작업 순서를 안내하고, 웹에서 작업 상황을 확인하는 졸업프로젝트입니다.

작업자는 상자와 나사를 보면서 안경에 표시되는 안내를 따라갑니다. 카메라 영상에서 작업대의 위치와 드라이버를 찾고, 현재 작업할 나사를 강조합니다. 관제 화면에서는 같은 작업의 영상과 진행 기록을 보고 저장한 영상을 내려받을 수 있습니다.

시연 작업은 상자에 뚜껑을 얹고 네 모서리의 나사를 순서대로 조립하는 과정입니다. 작업대 주변에는 ArUco 마커를 배치하고, 상자와 나사 A~D의 위치를 미리 등록했습니다. 작업 순서를 화면으로 안내하는 것과 실제 물체 위에 표시를 맞추는 것, 작업 상황을 원격으로 전달하는 것을 하나의 실행 흐름으로 연결했습니다.

현재 시연 환경은 **Galaxy Z Fold7 · Android 16 · VITURE Beast**입니다. 초기에는 Windows의 Python 인식 서버와 Unity로 구현했고, 이후 인식과 양안 출력을 휴대폰으로 옮겼습니다. 지금은 휴대폰과 안경을 USB-C로 연결해 실행합니다.

## 사용 흐름

상자 배치 → 뚜껑 닫기 → 나사 A → B → C → D → 최종 확인

안경에는 상자·뚜껑의 윤곽과 네 나사 위치가 표시됩니다. 네 위치를 함께 보여주되 현재 작업할 나사에만 상태 색을 넣습니다. 주황색은 접근 안내, 파란색은 작업 안내, 초록색은 다음 단계로 넘어가기 전의 안내이며, 한글 문구가 함께 바뀝니다. 최종 확인에서는 네 나사 표시를 민트색으로 통일합니다.

오른쪽 위에는 상자, 뚜껑, 나사, 조립된 상자를 단계에 맞춰 작은 3D 모델로 보여줍니다. 실제 물체를 따라가는 윤곽선과 달리 이 부품 미리보기는 시야의 일정한 위치에 둡니다.

상자와 뚜껑 단계는 추적이 유효한 시간을 각각 7초, 6초 누적하는 시간 기준으로 넘어갑니다. 나사 단계는 드라이버의 근접·유지 조건을 확인하고, 초록 안내가 표시된 뒤 3초 후 다음 나사로 넘어갑니다.

전체 안내는 최종 확인 화면을 약 10초 보여준 뒤 종료됩니다. 일반 단독 실행의 최대 작업 시간은 10분입니다. 별도로 남겨둔 진단 모드는 시험 목적에 따라 더 짧은 제한을 사용합니다.

웹 관제는 실시간 관제, 작업 기록, 저장 영상, 기기 설정으로 나뉩니다. 영상 공유와 서버 저장은 휴대폰에서 각각 동의해야 하며, 녹화 파일은 무음 영상으로 저장합니다. 웹에는 카메라 시점의 영상을, 안경에는 눈별로 투영한 AR 안내를 보여줍니다.

| 화면 | 확인하거나 조작하는 내용 |
| --- | --- |
| 실시간 관제 | 작업대 영상, 현재 단계와 안내, 나사 A~D 상태, 연결·추적 상태 |
| 작업 기록 | 최근 작업 세션의 단계 변화와 중단·종료 기록 |
| 저장 영상 | 촬영 시각, 길이, 용량, 저장 상태, 삭제 예정일, 다운로드·삭제 |
| 기기·설정 | 연결 코드 승인과 본인 계정에 등록된 기기 관리 |

영상 표시를 꺼도 영상 영역의 위치와 크기는 유지합니다. 작업 기록은 세션 단위로 구분해 최근 작업을 보여줍니다.

Fold7 Android 앱

AR 인식과 안내는 휴대폰에서 처리합니다. 인터넷 연결은 원격 관제와 서버 저장에 사용하며, 휴대폰과 관제 PC가 서로 다른 네트워크에 있어도 연결할 수 있습니다. 웹은 Vercel, 중계 서버는 AWS EC2에 배포했습니다.

### 작업대 위치 계산

Beast 카메라의 영상에서 OpenCV로 ArUco 마커의 ID와 모서리를 찾습니다. 등록된 작업대 좌표와 영상 좌표의 대응으로 PnP 자세를 구하고, 그 자세를 이용해 상자와 나사 위치를 카메라 기준 3차원 좌표로 변환합니다. 자세 계산에는 IPPE 후보 계산과 LM 보정을 사용하며, 재투영 오차와 해의 유효성을 확인한 뒤 안내에 전달합니다.

초기 구현은 마커가 일부 가려지면 안내가 자주 사라졌습니다. C3.2에서는 마커가 5개 이상 보이고 자세가 유효한 구간에서 모서리 기준을 모읍니다. 이후 3~4개만 보이면 학습한 모서리와 현재 관측을 대응시켜 자세를 다시 계산합니다. 여기서 학습은 실행 중의 기하 기준을 축적하는 과정입니다.

여러 관측으로 만든 기준끼리 계산 결과가 맞는지, 보이는 마커를 하나씩 제외해도 나사 위치가 일관적인지 확인합니다. 현재 관측으로 좌표를 갱신하며, 기준이 오래됐거나 위치 계산이 불확실하면 표시를 숨깁니다. 이 경로는 오버레이, 준비 시간 누적과 드라이버 위치 판단에 함께 적용했습니다.

관련 코드: [WorkspaceTracker](mobile/beast-fold7/app/src/main/java/com/lucita/beastgate/WorkspaceTracker.java), [LearnedCornerTracker](mobile/beast-fold7/app/src/main/java/com/lucita/beastgate/LearnedCornerTracker.java).

### 양안 오버레이

카메라와 착용자의 두 눈은 위치가 다릅니다. 카메라 영상에서 나사에 맞는 점을 안경 화면에 그대로 그리면 눈으로 봤을 때 어긋날 수 있어, 좌우 눈별 투영을 따로 처리했습니다.

1. 작업대 자세로 나사와 윤곽선의 카메라 기준 3차원 좌표를 구합니다.
2. 좌우 각각의 3×4 투영 행렬을 적용해 눈별 화면 좌표로 바꿉니다.
3. 좌표의 깊이·유효성·화면 범위를 검사하고 각 눈의 1920×1080 영역에 그립니다.
4. 두 영역을 합친 3840×1080 Full SBS 화면을 Android Presentation으로 Beast에 출력합니다.

나사 표시는 작은 반투명 구 형태로 그리고, 윤곽선과 한글 안내는 Canvas에서 처리합니다. 시야 고정 부품 미리보기에는 Three.js를 사용합니다. 눈별 투영은 기존 Unity 구현을 Android로 옮겼고, A~D 보정 파일은 유지했습니다. 정면과 가까운 거리, 측면 이동 후 정면 복귀 조건에서 착용자가 위치와 양안 겹침을 비교했습니다.

현재 보정은 고정된 작업대와 착용 조건에 맞춘 값입니다. 마커 배치, 안경 착용 위치, 화면 설정이 달라지면 정합을 다시 확인해야 합니다.

관련 코드: [EyeProjection](mobile/beast-fold7/app/src/main/java/com/lucita/beastgate/EyeProjection.java), [StereoOverlayView](mobile/beast-fold7/app/src/main/java/com/lucita/beastgate/StereoOverlayView.java).

### 도구 검출과 단계 전환

드라이버 검출에는 YOLO 모델을 ONNX로 변환해 사용했습니다. 휴대폰의 ONNX Runtime에서 640×384 입력으로 추론하고, 검출 결과를 원래 카메라 좌표로 되돌립니다. 도구 추론은 마커 추적·화면 갱신과 분리된 작업에서 처리합니다.

드라이버와 손잡이 검출을 이용해 끝 위치를 추정합니다. 손잡이 검출이 누락되면 드라이버 양 끝 중 등록된 나사에 가까운 쪽을 사용합니다. 이 영상 좌표를 나사 높이의 평면에 투영해 A~D와의 거리를 계산합니다. 작업대 안에서 도구 대상을 하나로 확정한 관측을 단계 판단에 사용합니다.

현재 나사 가까이에서 유효한 관측이 800ms 누적되면 진행 조건을 확보합니다. 그 뒤 4초의 작업 안내 시간을 두고, 다시 근접 조건을 만족하면 초록 안내로 전환합니다. 실제 초록 표시가 렌더링된 시점부터 3초를 센 뒤 다음 나사로 넘어갑니다. 각 단계의 시간 조건과 현재 대상을 함께 관리합니다.

관련 코드: [YoloDetector](mobile/beast-fold7/app/src/main/java/com/lucita/beastgate/YoloDetector.java), [ToolEvidence](mobile/beast-fold7/app/src/main/java/com/lucita/beastgate/ToolEvidence.java), [AssemblyProbe](mobile/beast-fold7/app/src/main/java/com/lucita/beastgate/AssemblyProbe.java).

### 관제와 영상 저장

웹에서 GitHub 계정으로 로그인한 뒤 휴대폰의 연결 코드를 승인합니다. 서버는 소유자별로 기기와 영상 접근을 제한하고, 상태와 영상은 별도 WebSocket 채널로 전달합니다. 저장 영상은 권한을 확인한 뒤 유효 시간이 짧은 다운로드 주소를 발급합니다.

휴대폰은 Android MediaCodec으로 카메라 영상을 H.264로 인코딩합니다. EC2는 인증된 영상 패킷을 관제 브라우저로 중계하고, 브라우저는 WebCodecs로 디코딩해 표시합니다. 녹화에 동의한 작업은 서버에서 수신 구간을 MP4로 묶어 비공개 S3 버킷에 저장합니다. PostgreSQL에는 소유자, 기기, 작업 이벤트와 녹화 파일의 상태·용량·만료 정보를 보관합니다.

기기 인증값과 웹 관제의 구독 권한은 분리했습니다. 브라우저에는 서버 서비스 키 대신 짧게 유효한 일회용 구독 티켓을 발급합니다. 상태 수신이 끊기면 지연 또는 연결 끊김으로 표시합니다. 녹화가 중간에 끊겼다가 복구된 경우에는 별도 구간으로 저장하되 원래 작업의 시간·용량 한도를 공유합니다.

전시 서버의 설정은 계정당 보관량 10GB, 영상 한 건당 300MB·최대 10분, 보관 기간 7일입니다. 시간이나 용량 한도 중 먼저 도달하는 조건에서 녹화를 마칩니다. 현재 운영 설정은 본인 계정 전용입니다.

관련 코드: [상태·영상 중계](mobile/beast-fold7/internet-supervisor/server/relay.ts), [녹화 처리](mobile/beast-fold7/internet-supervisor/server/recorder.ts), [S3 저장·다운로드](mobile/beast-fold7/internet-supervisor/server/s3-recordings.ts).

## 확인한 내용

C3.2에서 상자부터 최종 확인까지의 착용 시험, 좌우 마커 가림, 웹 작업 기록, 영상 저장과 다운로드를 확인했습니다. 통합 시험에서 내려받은 2분 1초 영상은 전체 819프레임을 정상 디코딩했습니다. 이 파일의 평균은 약 6.7fps이며, 목표는 30fps입니다.

2026년 11월 26일 소스 백업 시 서버 자동 테스트 125개와 서버·웹 TypeScript 검사를 통과했습니다. 장시간 연속 사용과 실제 7일 경과 삭제는 추가 확인이 필요합니다. 현재 검증 범위는 영상·시간 조건에 따른 작업 단계 안내이며, 체결 토크와 기계적 조립 품질은 별도의 계측이 필요한 항목입니다.

자동 테스트에서는 다른 소유자의 기기·영상 접근 차단, 연결 코드 만료와 중복 승인, 재연결·로그아웃 시 권한 처리, 녹화 중단 후 복구, 보관량 예약과 초과 거부 등을 검사했습니다. Android 쪽에서는 투영 좌표, 준비 시간, 상태 전이, 부분 마커 좌표가 실제 안내까지 전달되는 경로를 시험했습니다. 착용 시험은 숫자 로그와 별도로 원이 실제 나사에 맞는지 사용자 확인을 받았습니다.

시험 조건과 실패·수정 과정은 [C3.2 기록](mobile/beast-fold7/docs/PARTIAL_TRACKING_C32_20261125.md)에, 저장 정책은 [보관 한도 문서](mobile/beast-fold7/internet-supervisor/docs/STORAGE_LIMITS_20261125.md)에 정리했습니다.

## 실행 준비

### 기존 시연 기기

1. Beast를 Fold7에 연결하고 **Full SBS 3840×1080, 0DoF, Extra Large, 4.5m**으로 맞춥니다.
2. 확인된 착용 위치와 상자·마커 배치를 유지합니다. 시작할 때는 마커가 충분히 보이도록 작업대를 바라봅니다.
3. 원격 관제가 필요하면 앱에서 인터넷 관제를 켜고, 웹에서 해당 기기의 연결 상태를 확인합니다. 영상 공유와 서버 저장은 필요한 항목만 동의합니다.
4. 앱의 작업 시작을 누르고 상자부터 최종 확인까지 진행합니다. 작업 중에는 앱을 앞에 둡니다.
5. 종료 후 웹의 작업 기록과 저장 영상을 확인합니다. 저장 완료된 파일은 다운로드해 재생할 수 있습니다.

앱을 벗어나면 안내와 원격 연결이 종료되는 현재 동작이 있습니다. 다시 시작할 때는 AR 시작 여부와 인터넷 관제 연결 여부를 각각 확인해야 합니다.

### 소스에서 준비

이 저장소는 소스 보관본입니다. 새 환경에서 실행하려면 Android 개발 도구, 모델 가중치, 서명 키와 서버 환경변수를 별도로 준비해야 합니다. 일부 빌드·도면 스크립트에는 개발 PC의 경로가 남아 있습니다. 복원에 필요한 파일과 버전은 [전시 체크포인트](checkpoints/2026-11-26/README.md)를 참고하세요.

중계 서버의 의존성을 설치한 뒤 `mobile/beast-fold7/internet-supervisor`에서 실행하는 검사입니다.

```powershell
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
```

웹은 그 아래 `web` 폴더에서 별도로 의존성을 설치합니다. 환경변수 예제는 각 폴더의 `.env.example`에 있습니다. 인증정보, 모델, APK, 촬영 영상, PPT와 원본 로그는 공개 소스와 분리해 보관합니다.

## 이전 구현과 실험

Windows 버전의 실행 방법은 [관제 실행 안내](docs/beast_self_service_console.md)와 [런타임 문서](docs/current_runtime.md)에 남겨두었습니다. Unity 코드는 초기 양안 표시 구현으로 보관하며, 현재 앱은 Android의 표시 기능으로 실행합니다.

MediaPipe와 HMM을 결합한 구성은 향후 확장 설계로 보관하고 있습니다. 현재 Android 실시간 경로는 OpenCV 추적, YOLO 도구 검출과 시간 조건 기반 단계 판단으로 구성됩니다.
