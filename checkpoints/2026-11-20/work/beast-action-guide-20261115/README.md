# 한글 행동 안내 후보

2026-11-15. 기존 성공 실행 파일을 교체하지 않은 표시 전용 후보다.

## 변경 내용

- `--sbs-guidance --action-korean`으로 선택한다. 플래그가 없으면 기존 안내를 유지한다.
- 작은 단계 제목과 큰 행동 한 줄만 표시한다. 예: `나사 B · 2/4`, `나사 B를 조여주세요`, `드라이버를 떼어주세요`.
- PAUSED 등 내부 상태명 대신 작업대 보기, 연결 확인, 드라이버 보이기 등 필요한 행동을 표시한다. 오류 상태 자체를 숨기지 않는다.
- 기존 표시 안정화와 초록 안내 지연을 거친 결과를 문구로 변환한다. 기존 2초 지연 실행 설정은 그대로 함께 사용한다.
- A~D 보정, 윤곽 기하, 도구 판정, 진행 보존과 단계 전이는 수정하지 않았다.
- 한글 글꼴 Noto Sans KR Bold를 포함했다. OFL 라이선스는 소스의 글꼴 폴더에 있다.

## 보관 위치

- 최신 후보 Player: `player-v2/BeastAssemblyGuide.exe` (이전 후보는 `player/`에 보존)
- Unity 프로젝트 사본: `build-project/`
- 새 문구와 옵션 원본: 프로젝트의 `ActionGuidanceText.cs`, `SbsGuidanceOptions.cs`, `SbsGuidancePresenter.cs`
- 수정 전 해당 파일 백업: `before/`
- 성공본/보정/설정 비교: `protected-before.json`, `protected-after.json` (9개 전부 동일)

후보 실행 파일만 더블 클릭하면 실제 세션이나 보정이 연결되지 않는다. 다음 착용 확인 때 기존 성공 실행 인수를 그대로 사용하는 별도 후보 실행으로 연결한다. 관제 기본 실행 대상은 바꾸지 않았다.

## 검증 결과

- Unity 6000.3.25f1 Windows 빌드 성공: `build-retry.log`.
- NUnit: 491개 중 487개 통과, 실패 0, 생략 4. `unit-tests.xml`.
- 새 문구/옵션 검사 24개 포함. 2초 지연, 최종 확인, 오류 시 작업 지시 금지, 표시 안정화 경계 검사.
- 카메라 없는 기존 합성 입력을 실제 Player로 재생. `captures-visible/`의 49프레임에서 A~D 좌우 원 좌표, 비어 있지 않은 UI, TRACKING_LOST/PAUSED/STALE_POSE/연결 끊김/최종 확인 상태의 원 숨김 검사 통과.
- 한글 작업/이탈/보류 문구를 이미지로 직접 확인했다. 실물 정합과 착용 시 가독성을 검증한 것은 아니다.
- 최종 화면 검사는 짧은 합성 상태 구간 안에서 초록 문구까지 확인하기 위해 지연 옵션 없이 실행했다. 기존 2초 지연은 별도 로직 검사로 검증했고, 첫 Player 재생에서도 2초 지연 옵션을 사용했다.
- 첫 재생은 창 크기가 달라 고정 해상도 검사에 맞지 않았다. 두 번째 숨김 창은 UI를 그리지 않았다. 최종 재생은 보이는 1536x432 창에서 검사했다. 실패 캡처는 지우지 않고 따로 보관했다.

카메라/영상 촬영 없이 Unity 자체 화면만 저장했다. 모든 유한 재생 프로세스는 종료됐다. 기존 기기의 출력 설정을 바꾸지 않았다.

## 관제 연결

- 이후 A→B 실기 로그 `viture_aruco_rt_20261115_231943_44a8a46ba873`에서 세 색의 한글 안내와 S3 전환을 확인했다. 사용자 체감 평가는 아직 확정하지 않았다.
- `AI-Assembly-Console/profile.json`의 `action_guidance_directory`로 v2를 선택한다. 이 항목을 제거하면 기존 영어 실행으로 돌아간다.
- 관제 관리 실행은 상자 배치부터 최종 확인까지 유지하며, 웹 종료/창 종료로 정리된다. 별도 `start-korean-trial.ps1`은 기존대로 최대 180초, B 도달 후 종료한다.
- 관리 실행도 동일한 실행 파일 해시와 보호 파일을 검증한다. 보정, 서버 판단과 초록 2초 지연은 바꾸지 않았다.
- 연결 검사 14개 통과: `console-integration-tests.xml`. 미리 종료 신호가 있는 관리 실행에서 카메라와 Player를 시작하지 않는 것도 확인했다.
- 관제를 통한 한글 v2 전체 실기는 아직 진행하지 않았다.

## Windows 관제 실행 경로 수정

- 관제 실행 `dcee475f85bb4a0f8ae29ecfd3334e9d`는 Unity 시작 시 실패했다. Windows PowerShell 5.1이 BOM 없는 UTF-8 스크립트의 한글 작업 경로를 잘못 읽은 것이 원인이다.
- `run-korean-player.ps1`, `start-korean-trial.ps1`에 UTF-8 BOM만 추가했다. 본문 바이트는 동일하며 이전 파일은 `before/*.before-utf8-bom`에 보관했다. 실행 파일과 보정은 수정하지 않았다.
- `test-windows-launcher.ps1`을 Windows PowerShell 5.1로 실행해 재현했다. 수정 전 두 경로 검사와 실제 Player 호출 직전 검사가 실패했고, 수정 후 4개 검사 모두 통과했다.
- 검사는 `Start-Process`를 가로채므로 카메라와 Unity를 실행하지 않는다. 실물 전체 흐름 재시험은 별도다.
- 향후 이 실행 스크립트를 수정할 때 UTF-8 BOM을 유지하고 같은 검사를 실행한다.
