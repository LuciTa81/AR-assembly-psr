# A-B 이탈 확인 복구 후보 검증 (2026-11-15)

## 결론

기존 성공본과 A-D 보정은 유지했다. 새 옵션을 켠 후보에서만 잠깐 끊긴 이탈 확인을 이어간다.
저장된 숫자 로그에서 개선을 확인했으며 실제 안경에서의 체감 개선은 아직 미검증이다.
이번 작업에서는 카메라, Unity 실기, 사진 또는 영상 저장을 실행하지 않았다.

## 확인한 원인

대상 기록: handle-linked-flow-sessions/viture_aruco_rt_20261115_175806_0d047eb0f962

- A 단계는 74.817초, 완료 HOLD 이후 이탈 전환 대기는 61.024초였다.
- 완료 HOLD 기록은 유지됐다. 0.8초 HOLD 자체가 계속 지워진 것은 아니다.
- 이탈 확인 400ms를 모으는 중 드라이버 미검출 등이 발생해 이탈 누적이 초기화됐다.
- 398ms, 399ms까지 확인했으나 이어지는 미검출로 취소된 구간이 있었다.
- 첫 HOLD 이후 610프레임 중 자세 추적 유효 608프레임이었다. 이번 지연을 마커 손실만으로 설명할 수 없다.
- 영상이 없는 숫자 로그이므로 검출 결과를 실제 손 동작이나 체결 완료의 증거로 단정하지 않는다.

## 최소 변경

server/realtime/guidance_timing.py의 GuidanceTiming에 release_resume_ms를 추가했다.
기본값 0은 기존 동작이다. 시험 전용 실행기는 2000ms를 사용한다.

- 완료 HOLD가 있고 드라이버 미검출 또는 관측 대기 경계로 끊긴 경우에만 이미 확인한 이탈 시간을 보존한다.
- 마지막 유효 이탈 관측에서 최대 2초까지만 보존하며, 미검출 반복으로 만료 시각을 연장하지 않는다.
- 안 보인 시간은 400ms에 더하지 않는다.
- 새 관측에서 드라이버가 보이고 모든 나사에서 떨어졌다는 조건을 충족해야 누적을 이어간다.
- 나사 재접근, 중간 위치, 다른 나사 접근, 위치 불명, 복수 후보, 손상 데이터, 마커 손실, 입력 공백, 명시적 초기화는 이탈 누적을 폐기한다.
- 복구 경계 이전에 촬영된 결과라도 나사 재접근 등이 확인되면 이전 이탈 누적을 폐기한다. 해당 결과로 진행을 추가하지는 않는다.
- 근접 유지 800ms, 이탈 확인 400ms, 기존 미검출 완료 경로의 보호 조건, 파란 WORKING 후 초록 안내 지연 2초는 바꾸지 않았다.
- Unity 윤곽 표시, A-D 정합, 카메라 및 작업대 프로필은 수정하지 않았다.

## 검증

### 자동 검사

- 새 이탈 복구 검사: 37개 통과. 문제 재현 검사가 먼저 실패하는 것을 확인한 뒤 수정했다.
- 활성 tests 검사: 1044개 통과, 별도 GUI 미리보기 검사 1개 제외.
- 시험 실행 설정 검사: 6개 통과.
- 실행 전 파일/설정 확인: 통과. 카메라 캡처와 실제 모델 추론은 실행하지 않음.
- 별도 코드 검토에서 발견한 복구 경계 재접근 반례를 회귀 검사로 추가하고 해결했다. 재검토에서 추가 조기 전이 결함은 발견하지 못했다.

전체 검사 시 test_manual_target_window_selection_and_no_image_saving은 Tk의 init.tcl 로드 환경 오류로 실패했다.
관련 없는 GUI 코드는 수정하지 않았으며, 최종 활성 검사에서는 이 항목만 제외했다.
루트 전체 탐색은 outputs 아래 과거 백업 테스트의 상대 import 오류가 있어 활성 tests 경로로 한정했다.
