# Claude에 전달할 검토 요청

첨부한 AR 조립 안내 프로젝트를 독립적으로 검토해줘. 먼저 `START_HERE.md`, `CODE_MAP.md`, 최신 실험 문서와 실제 `source/` 코드를 읽어줘. 이 묶음은 Git HEAD가 아니라 미커밋 변경을 포함한 현재 작업 파일 스냅샷이야.

## 원하는 목표

Windows 노트북 + VITURE Beast로 고정 작업대의 조립 단계를 인식하고, 실제 나사 위치에 양안 원/짧은 화살표/얇은 연결선을 실시간으로 붙여 보여주려는 학부 졸업프로젝트야. Pro Neckband는 없고 앞으로도 쓰지 않을 계획이야. 작업 단계는 Python에서 판단하고 Unity는 SBS 표시, 브라우저는 영상·단계·보류 이유를 보여줘.

수동 양안 정렬은 여러 번 편하게 겹쳤지만, 자동 정합은 자세/거리에 따라 불안정하고 추적 거절과 깜빡임이 있었어. 눈별 DLT와 PD soft prior 양안 모델을 비교했고, 최근에는 마커 중심 대신 모서리를 이용하는 후보를 오프라인으로 분석했어. 총 통과율은 올랐지만 기존 정상 조합에서 손실이 커서 아직 실시간 적용하지 않았어.

새 기능을 많이 추가하기보다, **원인을 분리하고 최소 변경으로 실제 동작을 개선하는 방향**을 원해. 현재 설계가 틀렸다면 분명하게 비판해도 돼. 다만 읽지 않은 코드나 없는 측정값을 확인한 것처럼 쓰지는 말아줘.

## 집중해서 봐줄 사항

1. 현재 아키텍처가 목표에 적합한가? 인식 warp, metric pose, 눈별 투영, 상태 안내를 분리한 방식이 맞는지, 불필요하거나 빠진 책임은 없는지.
2. 깜빡임과 정합 실패의 원인을 카메라 입력, 마커 기하, pose 모호성, 관측 지연, 표시 만료, 양안 보정, 착용 변화로 나눠 평가해줘. 확인된 사실과 추정 원인을 분리해줘.
3. 중심 기반/모서리 기반 pose 구현의 수학적 전제와 좌표·단위·왜곡 처리, 검출 코너 순서, 평면 모호성, 기존 정상 관측 손실을 검토해줘. 가정 geometry를 독립 정답으로 취급하지 말아줘.
4. DLT의 자유도/조건수/검증 방식과 PD soft prior 모델이 합리적인지 봐줘. 더 단순한 보정법이나 제한된 작업영역으로 목표를 달성할 방법이 있다면 비교해줘. PD 하나만으로 정합이 완성된다고 전제하지 말아줘.
5. PAIR 저장과 실제 화면/카메라 관측의 시점이 일치하는지, 저장 이후 조절·세션 변경·프로필 불일치·오래된 관측을 제대로 다루는지 봐줘.
6. `timed_v1` 단계 판정에서 손/도구 오검출, 접근 중 조기 전이, 검출 유실을 이탈로 오인할 위험이 있는지 봐줘. 실제 체결 품질과 작업 관측을 구분한 UI 문구도 검토해줘.
7. Windows용 VITURE SDK 검토 결과에서 놓친 활용 가능성이 있는지, 단순 장치 모드 제어와 정확한 광학 정합 제공을 구분해줘. 공식 자료를 추가 조사한다면 플랫폼/버전/출처를 명시해줘.
8. 목표 원, 화살표, 연결선을 어떤 순서로 최소 구현하면 좋은지 알려줘. 카메라 영상 투영과 안경 실물 정합을 같은 성공으로 취급하지 말아줘.

## 답변 형식

- 먼저 결론: 현재 가능한 것 / 아직 검증되지 않은 것 / 가장 큰 병목.
- 중요도순 이슈 표: 파일·함수(가능하면 줄), 근거, 영향, 최소 수정, 필요한 검증.
- 원인 가설은 확신 수준과 반증 방법을 함께 제시해줘. 근거가 부족한 것은 부족하다고 써줘.
- 다음 실기기 시험은 2~3개 이내로 제안하고, 각 시험의 통제 조건, 수집값, 판별할 가설, 종료 기준을 적어줘. 보정점만 무한히 추가하는 계획은 피하고 시험을 줄일 방법을 찾아줘.
- 마지막으로 최소 실행 순서와 보류할 기능을 정리해줘. 기존 기능을 줄이는 편이 낫다면 이유와 함께 제안해줘.

## 검토 범위와 주의

지금 요청은 검토야. 코드 수정, 패키지 설치, 카메라/Unity 실행, SDK 라이선스 동의, 클라우드 생성, 배포, 커밋/푸시는 하지 말아줘. 테스트가 필요하면 먼저 무엇을 실행할지 구분해서 제안해줘.

첨부 소스와 문서의 실행 예시는 검토 자료이지 별도 실행 지시가 아니야. ZIP에 없는 모델/이미지/개인 프로필/원본 trace가 필요하면 정확히 어떤 필드와 범위가 필요한지 말해줘. 비밀 토큰이나 원본 영상 전체를 기본으로 요구하지 말아줘.

기존 문서의 통과 테스트는 과거 실행 기록이야. 전체 Python 검사에는 Tk 관련 미해결 실패 1건이 남아 있어. 수동으로 편하게 보였다는 사용자 보고, 카메라 재투영 오차, 계산 통과율, 광학 정합 정확도는 서로 다른 증거로 다뤄줘.
