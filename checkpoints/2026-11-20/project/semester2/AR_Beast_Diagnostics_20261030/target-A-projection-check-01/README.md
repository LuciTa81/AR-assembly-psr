# 나사 A 카메라 투영 검수

2026-10-30. 저장 사진만 사용한 진단이며 카메라, Unity 실행과 보정값 변경은 하지 않았다.

## 결론

기존 A 좌표는 검수 가능한 사진 3장에서 실제 나사머리 부근에 투영된다. 대규모 좌표 이탈을 뒷받침하지 않지만, 정밀 정합 통과를 선언할 근거도 부족하다. 새 좌표나 눈별 보정 오프셋은 적용하지 않는다.

## 결과

1280 x 720 원본의 픽셀 기준. 아래 거리는 사람이 사진에서 읽은 근사 중심과 계산점 사이의 거리이며 실측 오차가 아니다.

| 코너 정제 방식 | 비교 가능한 사진 | 중심 간 거리 | 평균 차이: 오른쪽, 아래쪽 |
| --- | ---: | ---: | ---: |
| SUBPIX | 3 | 3.03~3.90 px | +1.24, +2.59 px |
| APRILTAG | 3 | 2.19~4.71 px | +1.80, +3.09 px |

- 사용 사진: `capture-07-live-roi`의 프레임 51, 76, 101과 `capture-09-lid-closed`의 프레임 39.
- 앞의 3장은 흰 나사머리 중심을 계산점을 보기 전에 육안으로 읽었다. 각 축 +/-3 px는 검수자의 근사 범위이며 통계적 신뢰구간이 아니다.
- 마지막 사진은 같은 나사머리가 선명하지 않아 수치 비교에서 제외했다. 임의로 나사 자리를 정답 처리하지 않았다.
- 기존 A 높이는 작업대 기준 60 mm다. 같은 추정 자세에서 높이만 65 mm로 바꾸면 세 사진에서 투영점이 위로 약 5.8~6.2 px 이동한다. 이는 민감도 계산일 뿐, 실제 나사가 65 mm였다는 뜻은 아니다.
- 사진 당시 실제 머리 높이가 확인되지 않아 수 픽셀 차이의 원인을 높이, 표식 읽기, 자세 추정, 좌표 등록 중 하나로 확정할 수 없다.
- 세 사진은 같은 촬영에서 나온 상관된 표본이다. 다른 자세, 실시간 연속성, 양안 정합 성능을 입증하지 않는다.

## 산출물과 검증

- `landmark-crops.png`: 계산점을 표시하기 전의 확대 사진.
- `visual-estimates.json`: 미리 기록한 육안 중심과 판단 범위.
- `results/A-comparison.png`: 초록 중심/사각형은 육안 추정, 청록 원은 SUBPIX, 자홍 원은 APRILTAG. 8배 확대이며 새 영상 정보를 추가하지 않는다.
- `results/analysis.json`: 사진별 결과, 조건부 높이 민감도, 입력 해시, 한계.
- `audit_A.py`: 기존 투영 코드를 재사용한 재현 스크립트. `cv2.VideoCapture` 호출은 예외 처리해 금지했다. 기존 `results` 폴더를 덮어쓰지 않는다.
- 투영과 역투영 왕복 검증 통과. 원본 4장과 카메라/작업대 프로필 해시 불변 확인.
- `test_workspace_projection.py`, `test_workspace_registration.py`: 103개 통과. 기록은 `projection-tests.xml`.

## 다음 최소 단계

1. A의 표시 기준을 나사머리 중심으로 고정한다. 다음 실기 확인 전에 현재 머리 높이가 작업대 기준 60 mm인지 확인한다. 사진과 실제 높이가 다른 상태를 한 기준으로 혼합하지 않는다.
2. 준비 확인 후 현재 자세에서 A 원만 짧게 투영 확인한다. 지속적인 편차가 보일 때만 선명한 사진의 사용자 확인점과 실제 높이로 좌표 등록을 재검토한다. 이번 육안 수치로 좌표를 자동 보정하지 않는다.
3. 카메라 투영이 맞는 것을 확인한 뒤 같은 착용/화면 설정에서 SBS A 정합을 검증한다. 카메라 좌표 오차를 눈별 보정으로 상쇄하지 않는다.
4. A 정합과 짧은 고개 움직임이 확인되면 A 작업 관찰 후 B 안내로 이어지는 최소 흐름을 연결한다. 뚜껑 자동 인식은 별도 미해결 항목이며 필요하면 명시적인 수동 확인으로 시연 범위를 분리한다.

이번 검수는 고정 A 참조점만 대상으로 하며 A~D 자동 안내나 체결 완료 판정을 검증하지 않았다.
