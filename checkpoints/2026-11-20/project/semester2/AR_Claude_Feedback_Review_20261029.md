# Claude 피드백 대조 검토

검토일: 2026-10-29. 사용자 제공 피드백, 현재 작업 폴더의 코드, 기존 실험 기록을 대조했다.
이번에 실행한 것은 저장된 수치 fixture에 대한 homography 계산 1건이다. 카메라/Unity/서버/전체 테스트는 실행하지 않았고 코드·프로필·임계값을 변경하지 않았다.

## 결론

물리 배치와 입력 관측부터 정비하고, 눈별 보정점 추가 수집은 뒤로 미루자는 방향은 타당하다.
그러나 "소프트웨어는 충분하고 물리 셋업과 설정 세 개만 남았다"는 결론은 지나치게 단정적이다.
실제로는 배치 설정의 불일치, 상태/공간 표시 결합, 관측 신선도 정책, 미검증 양안 모델이 함께 남아 있다.
새 기능 확대보다 이 문제를 분리해서 해결해야 한다는 점을 받아들이는 것이 적절하다.

## 1. 이번에 추가 확인한 우선 문제

### P1: 단계 인식과 공간 추적이 서로 다른 마커 배치를 참조한다

- 기본 실시간 설정 `configs/realtime_viture_beast_aruco.yaml:22`는 `marker_layout_v2_session_17.yaml`을 읽는다.
- 이 파일의 4/5번은 예전 아래쪽 가운데/오른쪽 위치다.
- 현재 공간 추적 수치 fixture의 comfort-layout은 이동된 4=(75,175,0), 5=(330,175,0)mm를 사용한다.
- `aruco_tracker.py`는 검출 마커 개수와 전체 모서리의 RANSAC inlier 비율로 OK를 결정한다. 모든 검출 마커가 실제 변환 계산에 기여해야 하는 조건은 아니다.

저장된 `tests/realtime/fixtures/workspace_pose_comfort.json`의 검출 좌표를 현재 인식용 layout에 넣어, 코드와 같은 `cv2.findHomography(..., cv2.RANSAC, 8.0)`로 계산했다. 난수 seed는 0으로 고정했다.

| 마커 | 사용된 모서리 수 | 변환 후 해당 layout 좌표와의 오차 중앙값 |
| --- | ---: | ---: |
| 0 | 4/4 | 4.34 px |
| 1 | 4/4 | 2.23 px |
| 2 | 4/4 | 2.96 px |
| 4 | 0/4 | 315.27 px |
| 5 | 0/4 | 283.07 px |

검출 수는 5개, inlier 비율은 12/20=0.60으로 현재 최소 품질 0.25를 넘는다.
따라서 **이 fixture에서는 이동된 두 마커를 버리고도 OK가 가능**하다.

이 오차는 800x600 인식용 warp 좌표의 차이이며 실물 mm/안경 픽셀 오차가 아니다.
모든 실시간 프레임이 실패한다는 뜻도 아니다. 다만 현재 기본 설정의 배치 불일치를 독립적으로 재현했으므로, 다음 물리 배치 변경 전에 인식용 layout과 metric profile을 함께 점검해야 한다.
설정을 바꾼 뒤에는 ROI/기존 템플릿 좌표가 여전히 같은 의미인지 확인한다. 단순히 한 JSON을 다른 YAML로 바꾸면 끝나는 작업은 아니다.

### P1: 표시 성공과 광학 정확도를 과대 해석하면 안 된다

기존 기록은 fit 6점 단계 이후 fit 8 / 독립 check 2점까지 진행됐다. 앞서 만든 요약은 초기 6점 분석을 중심으로 설명했으므로 이 후속 기록을 함께 읽어야 한다.

최종 check에서 공동 모델의 눈별 오차는 5.739~13.547px였다. 두 점의 카메라 Z는 약 516/538mm이며, 알려지지 않은 시점의 안경 착용 변화도 보고됐다.
이 결과를 작업 범위 전체에서의 실물 3mm 정확도로 해석할 수 없다. 국소 민감도로 환산한 수치는 실제 오차 측정이 아니다.
정지대 반복성도 절대 정확도가 아니다. "나사 안내에 이미 충분하다"는 주장은 자동 추적의 독립 착용 평가 후에만 가능하다.

근거: `docs/beast_joint_fit_comparison_20261007.md:274`, `:303`, `:507`.

## 3. 특히 정정할 사실과 추론

### 카메라 속도는 요청 실험을 이미 했다

`docs/beast_tracking_diagnosis_20261006.md:121` 기록:

- 기본 설정: YUY2, 실제 약 100ms 간격.
- 30FPS 요청: FPS 속성은 약 30, 실제 약 100ms 간격.
- MJPG + 30FPS 요청: 읽힌 형식은 여전히 YUY2, 실제 약 100ms 간격.

지원 포맷을 정식 열거하는 작업은 가치가 있다. 하지만 MJPG 설정 한 줄을 추가하면 개선된다고 기대할 근거는 없다. OpenCV도 실제 속성 동작은 장치·드라이버·backend에 의존한다고 명시한다. [OpenCV Video I/O](https://docs.opencv.org/4.13.0/d4/d15/group__videoio__flags__base.html)

10fps + 만료 150ms만으로 "무조건 10% 공백"이 나오지는 않는다. 이상적인 100ms 갱신과 작은 지연이면 연속 표시도 가능하다. 실제 처리는 캡처 후 지연, 폴링 시점, 전체 RTT를 더한 보수적 만료, 프레임 거절이 결합돼 있다. 리뷰의 비율 계산은 특정 가정 모델이지 수학적 필연이나 새 실측이 아니다.

반대로 150ms를 절대 불변값으로 지킬 이유도 충분히 입증되지 않았다. 재측정 후 표시 정책을 조정할 수 있지만, 저장 데이터의 신선도까지 함께 느슨하게 만들 필요는 없다.

### 공간 표시와 상태 결합은 실제 존재한다

`GuidanceState.cs:92`는 상태 채널의 `marker_status != OK`를 TRACKING_LOST로 바꾸고, `CandidateProjection.cs:47`은 이 상태에서 원을 숨긴다.
따라서 별도 metric pose가 유효해도 원이 꺼지는 경로가 존재한다. 이 지적은 타당하다.
다만 두 실패율은 같은 입력을 공유해 상관관계가 있으므로 독립 확률의 곱처럼 설명할 수 없다. 한 단계가 먼저 거절하면 뒤쪽 만료가 집계되지 않아, TRACKING_LOST 비율만큼 표시율이 그대로 오를 것이라고 보장할 수도 없다.

### 검출기를 합치는 것은 가능성이지 즉시 단순화가 아니다

현재 인식용 tracker는 이미 마커 모서리를 사용하고, metric 기본 pose는 중심을 사용한다. 서로 다른 잔차와 좌표계를 가진다.
metric pose에서 평면 homography를 유도할 수 있지만, 왜곡 처리, 방향/역행렬, metric 좌표에서 기존 800x600 ROI 좌표로 가는 변환이 필요하다. pose 성공만으로 ROI/도구 인식 성공이 보장되지는 않는다. [OpenCV Homography](https://docs.opencv.org/4.10.0/d9/dab/tutorial_homography.html)

### 광학 문제를 새 모델 하나로 종결할 수는 없다

장치 고정 성분과 눈 위치 성분을 분리하는 접근은 검토할 가치가 있다. 관련 연구도 선행 eye-display 보정과 사용자 시점 갱신을 구분한다. 다만 연구의 HoloLens/RGB-D 구성과 Beast 단안 UVC/미확인 광학 모델은 다르다. [회전 제약 OST 보정 연구](https://arxiv.org/abs/2108.10603)

화면의 4.5m 설정을 실제 초점거리로 단정하거나, 두 점만으로 재착용 보정이 충분하다고 결론 내리지 않는다. 현재 자료에서 복시의 원인도 광학 융합 하나로 확정되지 않았다.

## 4. 수정된 최소 실행 순서

1. **배치 기준 일치:** 새 기능 전에 기본 인식 layout과 comfort metric profile의 불일치를 해결할 후보를 만든다. ROI 좌표 호환성을 확인하고 현재 fixture의 4/5 제외 현상을 회귀 검사로 고정한다.
2. **작업대 기하 확정:** 고정된 평탄 보드를 우선 고려한다. 검은 외곽, 중심/회전, 목표 높이, 실제 작업 자세의 가시성을 확인한다. 표면에 얹은 종이와 원점 위치까지 포함해 등록한다.
3. **관측/표시 경로 정리:** 상태와 공간 품질을 구분하고, 만료/모호성/품질 거절을 분리한다. JPEG/폴링을 측정 후 한 가지씩 줄인다. 지원 모드 조사는 기존 요청 실험과 구분한다.
4. **짧은 카메라 검증:** 같은 배치에서 고정 구간과 작은 움직임 구간을 분리해 수치 관측과 A-D 영상 투영을 검사한다. 양안 조절은 하지 않는다. 여기서 실패하면 원 맞추기 수집으로 넘어가지 않는다.
5. **제한 범위의 양안 검증:** 선택한 작업 거리·시야 범위, 같은 착용에서 기준점과 독립 자세를 확인한다. 한 눈씩 위치와 양안 깊이를 구분한다. 필요할 때만 모델 비교와 새로운 보정 세트를 설계한다.
6. **안내 UX 확장:** 현재 나사 원, 고정된 짧은 화살표, 얇은 연결선. 단계 인식·공간 표시·체결 확인의 의미를 분리해 시연한다.

성공 조건은 "원 노출률" 하나가 아니라 정상 작업 구간의 위치 오차, 가시 시간, 유실 시 동작, 양안 편안함, 조기 단계 전이를 각각 기록하는 것이다. 허용 mm는 실제 나사 크기와 안내 목적을 확인한 뒤 정한다.
하루 또는 착용 1~2회로 완료된다는 일정은 현재 증거로 보장할 수 없다. 다음 시험에서 원인을 좁힐 수는 있지만 결과를 미리 성공으로 전제하지 않는다.

## 현재 상태를 한 문장으로

**소프트웨어 기반은 갖춰졌지만, 이동된 물리 배치와 서로 다른 추적 설정을 일치시키고 표시 정책을 정리한 뒤 제한된 작업 범위의 양안 정합을 검증해야 하는 단계다.**
